# 14 — i18n: locale + translation catalog

Verve owns the locale resolution chain; the actual translation
table is yours to ship in whatever shape fits your stack.

## Locale resolution

```zig
const en_es: verve.I18nCatalog = .{
    .entries = &.{
        .{ .locale = "en", .key = "greeting", .value = "Hello" },
        .{ .locale = "es", .key = "greeting", .value = "Hola" },
    },
    .default_locale = "en",
    .supported = &.{ "en", "es" },
};

fn renderHome(ctx: *verve.Context) !*verve.Node {
    const locale = try verve.resolveLocale(
        en_es,
        ctx.request_meta,
        ctx.location,
        ctx.alloc(),
    );
    const greeting = en_es.lookup(locale, "greeting");
    return ctx.h1(greeting).build();
}
```

The resolver walks (first match wins):

1. `lang=<locale>` cookie (set by your own preference UI).
2. `?lang=<locale>` query parameter.
3. `Accept-Language` header — first supported candidate, with a
   language-prefix fallback (`fr-CA` → `fr`).
4. Catalog default.

Unsupported locales are ignored at every step, so a `lang=xx` cookie
where `xx` isn't in `supported` falls through to the next stage.

## Catalog lookup

```zig
catalog.lookup(locale, "key")
```

- Exact match on `(locale, key)` returns its value.
- Missing key in the requested locale falls back to the default
  locale.
- Missing in both returns the key itself (so untranslated UI shows
  the key, easy to spot during dev).

Lookup is linear over `entries` — fine up to a few hundred entries.
Switch to a hashmap-backed catalog once profiling shows a hot path.

## Catalog shape

`I18nEntry` is `{ locale, key, value }`. Where the entries come from
is your decision:

- Comptime: write the slice literal directly in your app, like the
  example above.
- Build-time: walk a `--i18n-dir locales/` in `build.zig` and emit a
  generated `i18n_entries.zig`. Mirror the `buildPublicAssets`
  pattern.
- Runtime: parse JSON / YAML at startup; build the `entries` slice
  once into an arena that lives for the process.

## Route-prefix locales

`/:locale/...` routes work today because path parameters are
first-class:

```zig
verve.Route.init("/:locale/home", renderHome),

fn renderHome(ctx: *verve.Context) !*verve.Node {
    const locale = ctx.param("locale") orelse "en";
    if (!en_es.isSupported(locale)) return ctx.redirect("/en/home");
    // …
}
```

Combine with the cookie-based path when you want sticky locale
choice independent of URL.

## Persisting locale choice

Issue a `lang=<locale>; Max-Age=31536000; Path=/; SameSite=Lax`
cookie when the user picks a language. The framework only writes the
CSRF cookie itself — additional Set-Cookie headers go through your
action handler.

## Lazy catalogs (`LazyCatalog`)

For very large multi-locale sets, `LazyCatalog` ships each locale as a separate
embedded JSON blob and parses + caches only the active (and default-fallback)
locale on first use — instead of baking every locale into one comptime array.
Single-binary distribution is preserved (blobs are `@embedFile`d).

Author catalogs as `i18n/<locale>.json` (flat `{ "key": "value" }`); the build
walks the dir (override with `-Di18n-dir`, default locale via `-Di18n-default`)
and generates an `i18n_catalog` module:

```zig
const std = @import("std");
const verve = @import("verve");
const catalog = @import("i18n_catalog"); // build-generated

var cat = verve.I18nLazyCatalog.init(catalog.locales, catalog.default_locale, gpa);
const locale = try verve.resolveLocale(&cat, meta, loc, arena);
const greeting = cat.lookup(locale, "greeting"); // lazy-parses `locale` once
```

`lookup` falls back locale → default → key. Back it with a process-lifetime or
arena allocator (parsed data is cached for the process and not individually
freed); lookups are guarded by a mutex for the server worker pool. The comptime
`Catalog` remains the right choice for small sets (zero runtime cost).
`resolveLocale` accepts either catalog type.

## RTL direction

```zig
verve.i18nIsRtl(locale: []const u8) bool
verve.i18nDir(locale: []const u8) []const u8   // "rtl" | "ltr"
```

Returns `true` / `"rtl"` for the 10-language RTL set: `ar`, `he`,
`fa`, `ur`, `ps`, `sd`, `ug`, `yi`, `dv`, `ckb`. Comparison is
case-insensitive; locale subtags (`ar-EG`, `fa_IR`) are handled by
stripping everything after the first `-` or `_`.

Use `verve.i18nDir` to set the `dir` attribute on `<html>`:

```zig
ctx.html(.{ .lang = locale, .dir = verve.i18nDir(locale) }, ...)
```

## Plural categories

```zig
verve.PluralCategory  // enum { zero, one, two, few, many, other }
verve.pluralCategory(locale: []const u8, n: u64) PluralCategory
```

Returns the CLDR cardinal plural category for integer `n` in
`locale`. Decimal operands are not modeled — pass the integer part
only. Unknown locales fall through to English-type rules (`1` → one,
everything else → other).

Supported plural families:

| Family | Locales | Rules |
|---|---|---|
| English-type | en, de, nl, … (default) | 1 → one; else → other |
| French | fr | 0–1 → one; else → other |
| East Slavic | ru, uk | m10=1 ∧ m100≠11 → one; m10 2–4 (not 12–14) → few; else → many |
| Polish | pl | n=1 → one; m10 2–4 (not 12–14) → few; else → many |
| Czech/Slovak | cs, sk | 1 → one; 2–4 → few; else → other |
| Arabic | ar | 0 → zero; 1 → one; 2 → two; m100 3–10 → few; m100 11–99 → many; else → other |
| Asian (other-only) | ja, zh, ko, th, vi, id, ms, lo, my, km | always → other |

## Plural-aware lookup — `tPlural`

```zig
verve.tPlural(
    catalog: verve.I18nCatalog,
    locale: []const u8,
    key_base: []const u8,
    n: u64,
    arena: std.mem.Allocator,
) ![]const u8
```

Looks up `key_base.<category>` (e.g. `items.one`, `items.few`).
Falls back to `key_base.other`, then `key_base` itself. Every `{n}`
token in the matched value is replaced with the decimal string of `n`.

Example:

```zig
// Catalog entries: "items.one" = "{n} item", "items.other" = "{n} items"
const label = try verve.tPlural(catalog, locale, "items", count, ctx.alloc());
// count=1 → "1 item", count=5 → "5 items"
```
