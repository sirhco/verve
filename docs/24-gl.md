# 3D engine (`verve.gl`)

Native 3D rendering for Verve apps — a three.js replacement built the
Verve way: the entire engine (scene graph, transforms, culling state,
draw ordering, asset parsing) lives in pure Zig and runs in wasm; the
browser side is one small, dumb WebGL2 interpreter inside
`src/bridge/verve.js` that walks a binary command stream out of linear
memory and issues GL calls. No three.js, no GL state machine in JS, no
copies of vertex data crossing the boundary.

Shipped so far (phases P1–P2 of five): scene graph + math, the frozen
binary wire contract, an unlit vertex-color pipeline, and the full
asset pipeline — `.glb` in at build time, packed `.vmesh` out, fetched
into wasm at runtime and rendered with a textured, simply-lit shader.
Demo: the `/gl` route (`zig build run`).

**Roadmap** (spec'd, in order): P3 PBR über-shader + image-based
lighting; P4 orbit controls, BVH picking, declarative `ctx.glScene`;
P5 verve.anim integration (tween-able camera/node/material paths,
scroll-scrubbed 3D). WebGPU arrives later as a second interpreter over
the same command stream — the wire format is deliberately API-neutral.

## Architecture — one command stream

```
wasm (Zig)                                      JS bridge
─────────────────────────────────────────      ─────────────────────────
scene graph (SoA, dirty flags)                  rAF loop calls the chunk's
  → world-matrix propagation                    frame export each tick
  → encode flat binary command stream     →     walks [tag][size][payload]
    into a fixed buffer in linear memory        records, issues WebGL2 calls
                                                zero-copy typed-array views
```

The wire contract's single source of truth is
`src/core/gl/command.zig`. Its golden tests freeze the byte layout —
they are the JS interpreter's conformance fixtures, exactly the
`serialize.zig` pattern verve.anim uses. Records are
`[tag: u16 LE][payload_size: u16 LE][payload]`, u32-aligned, preceded
by a u32 total-length header; unknown tags skip via `payload_size`
(forward compatibility). Bulk data (vertex bytes, GLSL source,
matrices, texels) never enters the stream — records carry `(ptr, len)`
into wasm memory and the interpreter reads it in place.

Tags v1: `BEGIN_FRAME`, `CREATE_BUFFER`, `CREATE_SHADER`,
`SET_PIPELINE`, `DRAW` (P1) plus `CREATE_TEXTURE`, `BIND_TEXTURE`,
`DRAW_SUB` (P2, additive — P1 bytes untouched). Resources are u32
handles created once; frames reference handles only.

Shader variants are a bitset on `CREATE_SHADER`:
`variant_vertex_color` (pos f32x3 @0 + color f32x3 @12, stride 24,
unlit) and `variant_lit_uv` (pos @0 + normal @12 + uv @24, stride 32,
texture × base-color × fixed-light lambert). The GLSL ships from Zig as
`(ptr, len)` so the bridge stays logic-free.

## Module layout

```
src/core/gl/          pure Zig, target-agnostic (native tests + wasm chunks)
  gl.zig              module root — verve.gl / chunk import gl via verve.gl
  math.zig            Vec3/Quat/Mat4, column-major f32, RH, WebGL clip space
  scene.zig           Scene(cap): flat SoA arrays, pre-order dirty propagation
  command.zig         THE wire contract: encoder, tags, GLSL, golden tests
  mesh.zig            unit cube in the vertex-color layout
  vmesh.zig           .vmesh packed asset format: native writer + freestanding reader
  png.zig             pure-Zig PNG decode (8-bit RGB/RGBA) + store-mode encode
  gltf.zig            .glb parser → vmesh-ready Model (native: std.json)
  fixture.zig         procedural textured-cube .glb (tests + demo asset)
tools/
  gen_demo_glb.zig    writes fixture cube as .glb (build step)
  gl_asset_gen.zig    .glb → .vmesh converter (build step)
```

`Scene` is struct-of-arrays with fixed capacity: nodes append in
pre-order (parent index always lower), so world-matrix propagation is
one linear pass and a clean subtree costs nothing. Node indices are
stable and will double as animation target ids in P5.

## Asset pipeline

Everything is build-time and procedural — no binary fixtures in the
repo:

```
fixture.zig ──gen_demo_glb──▶ demo.glb ──gl_asset_gen──▶ demo.vmesh
   (or your own .glb)                                        │
                                              embedded + served at
                                              /gl/demo.vmesh (HTTP)
```

`.vmesh` is a zero-parse format: header, submesh table (index range +
PBR base-color factor + texture index), texture table, then interleaved
vertex data (16-aligned), u16 indices, and raw mip-0 RGBA8 texels — laid
out so the runtime fetches the file, drops it into linear memory, and
points `CREATE_BUFFER`/`CREATE_TEXTURE` records straight at the bytes.
The reader (`vmesh.Reader`) is freestanding-safe, allocation-free, and
hardened against hostile headers (all size math u64-widened; truncation
and overflow return errors, never panic). The glb parser and PNG
decoder are similarly defensive — `gl_asset_gen` fails the build loudly,
naming the offending file.

glTF support today: static meshes, multiple primitives/materials,
pbrMetallicRoughness base-color factor + base-color texture (embedded
PNG), u16 indices, f32 attributes. Deferred: node transforms (flattened
without baking — P-later), skinning/morph, Draco/meshopt, KTX2, JPEG
(convert to PNG before importing).

Runtime loading: an island calls the `gl_load` chunk import with a URL
and a callback export name; the bridge fetches, copies the bytes into
the chunk arena (`verve_chunk_alloc`, same path drag-drop uses), and
invokes the callback with `(ptr, len)` — `(0, 0)` on failure, in which
case the island keeps rendering its no-asset frames. Note the chunk
arena is 256 KB total; large models need the planned dedicated asset
region.

## Driving a canvas from an island

The imperative surface (the declarative `ctx.glScene(...)` wrapper
lands in P4): SSR a `<canvas data-ref="...">` inside an island, and in
the chunk:

```zig
const verve = @import("verve");
const gl = verve.gl;

extern "verve" fn gl_start(ref_handle: i32, name_ptr: [*]const u8, name_len: u32) void;

export fn hydrate(_: u32, _: u32, _: u32) void {
    if (verve.queryRef(@as([]const u8, "my-canvas"))) |h|
        gl_start(h, "my_frame".ptr, "my_frame".len);
}

export fn my_frame(dt_ms: f32, width: u32, height: u32) u32 {
    // mutate scene, updateWorld(), encode commands…
    // return a pointer to the length-prefixed stream; 0 stops the loop.
}
```

The bridge owns the rAF loop, dpr-aware canvas sizing, and context
setup; a faulting stream stops the loop with a console error instead of
dying silently. WebGL2-less environments log and leave the canvas
inert (SSR content stands).

**One stateful gl island per page.** Island chunks share the main
client's linear memory, and every chunk links its static data at the
same base address — two chunks with mutable statics on one page clobber
each other (see the islands guide). That's why the `/gl` demo drives
both canvases from a single `GlDemo` chunk with two frame exports. A
framework-level fix (per-chunk data regions) is on the roadmap.

## Demo

`zig build run` → `http://127.0.0.1:8080/gl`: an unlit vertex-color
cube (P1 path, stride-24 variant) and a checkerboard-textured, lit
model loaded through the full pipeline (P2 path, stride-32 variant) —
`src/client/islands/GlDemo.zig` is the reference implementation for
everything on this page.

## Testing

All engine logic tests run natively — no browser:
math goldens, scene propagation, byte-exact wire goldens (the Zig↔JS
contract), vmesh round-trip + hostile-header rejection, PNG codec
round-trip + per-filter goldens, glb fixture → parser round-trip, and
an asset-gen chain exercised by the build itself. Visual verification
is the `/gl` route (headless Chrome + SwiftShader works:
`--headless=new --use-angle=swiftshader --screenshot=...`).
