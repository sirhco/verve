# 3D engine (`verve.gl`)

Native 3D rendering for Verve apps — a three.js replacement built the
Verve way: the entire engine (scene graph, transforms, culling state,
draw ordering, asset parsing) lives in pure Zig and runs in wasm; the
browser side is one small, dumb WebGL2 interpreter inside
`src/bridge/verve.js` that walks a binary command stream out of linear
memory and issues GL calls. No three.js, no GL state machine in JS, no
copies of vertex data crossing the boundary.

v1 feature-complete (phases P1–P5): scene graph + math, the frozen
binary wire contract, an unlit vertex-color pipeline, the full asset
pipeline — `.glb` in at build time, packed `.vmesh` out — a full
PBR über-shader with image-based lighting, directional/point lights,
vmesh v2 (tangents + complete material set), and a dedicated client
asset region; then in P4: damped orbit camera, BVH ray-picking, GPU
resource registry with context-restore replay, the declarative
`ctx.glScene(...)` builder + `GlScene` island chunk, and complete
GPU lifecycle management (DELETE_RESOURCE, unmount teardown,
webglcontextlost/restored, poster swap); then in P5: verve.anim
integration — `glTarget`/`glTargetFrom`/`glTargetRange` tween
builders that drive gl scene properties (camera yaw/pitch/distance,
material metallic/roughness, model yaw) via a frozen target-id
encoding and a setter trampoline registered in the island chunk, plus
a scroll-scrubbed demo on `/gl-scene`; then in P6: anim completion —
node-rotation + emissive tween paths, SSR-side gl tweens
(`resolvePathStatic`), a single shared anim+gl rAF tick (no more P5
frame lag), a per-submesh scene graph in `GlScene` with
inverse-transform picking, and `Mat4.invert` / `ray.transformRay` /
`bvh.walkRange`. Demos: `/gl` (imperative
reference) and `/gl-scene` (declarative + scroll scrub).

**WebGPU (P10–P11, COMPLETE)**: a second interpreter over the same frozen command
stream. All P10 slices shipped — unlit cube (`/gl-webgpu`), textured PBR + IBL + PCF
shadow (`/gl-scene-webgpu`), and the real asset-driven `GlScene` (`/gl-scene` + the
other `glScene` routes) feature-detects `navigator.gpu` and renders through WebGPU
when available, falling back to WebGL2 otherwise. P11 brought it to functional
parity with WebGL2: multi-instance (`/gl-multi` renders multiple GlScene islands via
WebGPU), `DELETE_RESOURCE`, and `device.lost` restore. WGSL shaders are generated in
Zig alongside the GLSL; the binary command stream is fully backend-agnostic. See the
P10 + P11 sections below.

**Deferred to v1.x** (recorded): onPick→named-export dispatch, cascaded /
multi-light shadows, co-locating DIFFERENT stateful chunks on one page (the
data-segment memory-partition track). (`Mat4.invert` shipped in P6; P9 render
quality complete — variants slice 1, frustum culling slice 2, directional shadow
map slice 3; P7 multiple instances of one stateful gl island per page shipped.)

## Lights

`GlSceneBuilder` accepts up to `max_lights = 4` mixed directional / point / spot
lights, appended one at a time with fluent methods and serialized into the
`data-gllights` canvas attribute as a flat CSV of 16 f32 per light (v0–v3 strides):

```
v0: [type_f32,   pos.x,  pos.y,  pos.z]     // type: 0=dir, 1=point, 2=spot
v1: [dir.x,      dir.y,  dir.z,  range]
v2: [color.r,    color.g, color.b, intensity]
v3: [cos_inner,  cos_outer, _pad, casts_shadow_f32]
```

The three light types:

- **Directional** (type 0) — infinite parallel rays; intensity is linear; `pos`
  ignored; `dir` normalized on write. Added via `.light(LightOpts)`.
- **Point** (type 1) — omnidirectional; `1/d²` range attenuation up to `range`
  meters; `dir` ignored. Added via `.pointLight(Light)`.
- **Spot** (type 2) — cone; `1/d²` range attenuation; cone falloff
  `smoothstep(cos_outer, cos_inner, dot(-L, dir))` gives a soft penumbra.
  `inner_deg` / `outer_deg` are converted to cosines on write. Added via
  `.spotLight(Light)`. Set `casts_shadow = true` to make it the depth-pass caster.

Builder:

```zig
ctx.glScene(.{ .src = ..., .env = ..., .poster = ... })
    .spotLight(.{ .pos = .{ 0, 6, 1 }, .dir = .{ 0, -1, -0.15 },
                  .color = .{ 1, 0.95, 0.85 }, .intensity = 60,
                  .inner_deg = 14, .outer_deg = 22, .range = 20,
                  .casts_shadow = true })
    .light(.{ .dir = .{ -0.4, -0.7, -0.4 }, .intensity = 0.6 })
    .pointLight(.{ .pos = .{ -3, 2, 2 }, .color = .{ 0.3, 0.5, 1.0 },
                   .intensity = 12, .range = 10 })
    .build();
```

`.lights([]const Light)` bulk-appends a pre-built slice. Props is frozen at 14
fields; lights travel out-of-band via `data-gllights` (back-compat: a single
`Props` directional light is used when the attribute is absent).

## Shadows

One light per scene can be designated as the depth-pass caster (`casts_shadow =
true`). Three caster types are supported:

- **Directional shadow** — the `light_vp` matrix is an ortho projection looking
  along the light direction, fitted to a fixed scene volume. Same depth pass and
  3×3 PCF lookup as the spot path.
- **Spot shadow** — `light_vp` is a perspective projection: `fovy = 2 × outer_deg`,
  aspect 1:1, near 0.1, far = `range`. The cone frustum naturally clips the shadow
  to the spot's illuminated cone; the existing light-frustum culling then skips
  shadow casters outside that frustum.
- **Point shadow** — omnidirectional shadow via a 6-face 2D atlas (1536×1024,
  3×2 of 512² tiles). Linear distance is packed RGBA8; the receiver face-selects
  the correct tile from the atlas and applies manual 3×3 PCF. Shader variant
  `variant_shadow_point = 1<<15`. Reuses the single-caster model (dir/spot/point).
  Demo: `/gl-point`.

All paths reuse the same depth framebuffer and shadow-pass light-frustum culling
(so out-of-frustum / out-of-cone geometry is skipped in the depth draw).

**Deferred:** simultaneous casters (currently one caster per scene); cascaded
shadow maps / CSM; area lights.

## Architecture — one command stream

```
wasm (Zig)                                      JS bridge
─────────────────────────────────────────      ─────────────────────────
scene graph (SoA, dirty flags)                  rAF loop calls the chunk's
  → world-matrix propagation                    frame export each tick
  → encode flat binary command stream     →     walks [tag][size][payload]
    into a fixed buffer in linear memory        records, issues WebGL2 calls
                                                zero-copy typed-array views
```

The wire contract's single source of truth is
`src/core/gl/command.zig`. Its golden tests freeze the byte layout —
they are the JS interpreter's conformance fixtures, exactly the
`serialize.zig` pattern verve.anim uses. Records are
`[tag: u16 LE][payload_size: u16 LE][payload]`, u32-aligned, preceded
by a u32 total-length header; unknown tags skip via `payload_size`
(forward compatibility). Bulk data (vertex bytes, GLSL source,
matrices, texels) never enters the stream — records carry `(ptr, len)`
into wasm memory and the interpreter reads it in place.

Tags v1: `BEGIN_FRAME`, `CREATE_BUFFER`, `CREATE_SHADER`,
`SET_PIPELINE`, `DRAW` (P1) plus `CREATE_TEXTURE`, `BIND_TEXTURE`,
`DRAW_SUB` (P2, additive — P1 bytes untouched). Resources are u32
handles created once; frames reference handles only.

P3 adds four tags: `CREATE_TEXTURE_EX` (tag 10, uploads RGBA16F cubemap
faces with precomputed mip levels — `generateMipmap` is never called;
`TEXTURE_MAX_LEVEL` is set to match the prefiltered chain),
`SET_LIGHTS` (tag 11), `BIND_IBL` (tag 12), `DRAW_PBR` (tag 13).
Stream-order rule: `SET_PIPELINE` must precede `SET_LIGHTS` and
`BIND_IBL` in every frame.

P4 adds one tag: `DELETE_RESOURCE` (tag 14) — frees a GPU object and
nulls the bridge's handle slot. Payload: `kind: u32` (0=buffer,
1=texture, 2=shader), `handle: u32`. Issued on island unmount and when
replacing resources. P3 bytes are untouched — P4 is strictly additive.

P8 adds one tag: `CREATE_TEXTURE_SRGB` (tag 15) — identical 20-byte
payload to `CREATE_TEXTURE` (tag 7), but the bridge uploads with an
`SRGB8_ALPHA8` internal format (hardware sRGB decode) for base-color and
emissive material maps. Strictly additive; tags 1–14 untouched.

Shader variants are a bitset on `CREATE_SHADER`:
`variant_vertex_color` (pos f32x3 @0 + color f32x3 @12, stride 24,
unlit), `variant_lit_uv` (pos @0 + normal @12 + uv @24, stride 32,
texture × base-color × fixed-light lambert), and `variant_pbr` (full
Cook-Torrance GGX + split-sum IBL + ACES tonemap; `variant_normal_map`
and `variant_emissive` are additive sub-bits). The GLSL ships from Zig
as `(ptr, len)` so the bridge stays logic-free. The PBR shader is a
comptime über-shader; GLSL source is hashed with FNV-64 and frozen by
golden tests.

**Uniform/sampler contract (PBR variant)**:

| Slot | Name | Content |
|------|------|---------|
| tex 0 | `u_base_tex` | base-color RGBA8 |
| tex 1 | `u_mr_tex` | metallic-roughness (B=metallic, G=roughness, glTF) |
| tex 2 | `u_normal_tex` | normal map (variant_normal_map) |
| tex 3 | `u_emissive_tex` | emissive RGBA8 (variant_emissive) |
| tex 4 | `u_occlusion_tex` | AO map |
| tex 5 | `u_irradiance` | IBL irradiance cubemap (RGBA16F 32²) |
| tex 6 | `u_prefiltered` | IBL specular cubemap (RGBA16F 128², 6 mip levels) |
| tex 7 | `u_brdf_lut` | split-sum BRDF LUT (RGBA16F 64², A/B terms in RG) |

Material block: 12 f32 — base-color RGBA | metallic, roughness,
occlusion strength, normal scale | emissive RGB, 0. Light packing:
8 f32 per light × max 4 lights — type (0=dir, 1=point), intensity,
position/direction XYZ, color RGB. sRGB decoding is done **in hardware**
(P8): base-color and emissive textures upload with an `SRGB8_ALPHA8`
internal format (`CREATE_TEXTURE_SRGB`, tag 15) so the GPU returns linear
values on sample — the shader no longer applies an in-shader `pow(2.2)`.
normal/metallic-roughness/occlusion are treated as linear (plain
`CREATE_TEXTURE`, tag 7).

  registry.zig        Registry(cap): record/replay GPU create-calls for context restore
  anim_target.zig     frozen target-id encoding (u32 kind/submesh/field) + path resolver

  gen_demo_hdr.zig    writes a simple studio HDR as Radiance RGBE (build step)
  gl_asset_gen.zig    .glb → .vmesh (with BVH bake + name table) and .hdr → .venv

`Scene` is struct-of-arrays with fixed capacity: nodes append in
pre-order (parent index always lower), so world-matrix propagation is
one linear pass and a clean subtree costs nothing. Node indices are
stable; the P5 target-id scheme reserves the `model` kind for
node-level properties (see the P5 section).

## Asset pipeline

Everything is build-time and procedural — no binary fixtures in the
repo:

```
fixture.zig ──gen_demo_glb──▶ demo.glb ──gl_asset_gen──▶ demo.vmesh
   (or your own .glb)                                        │
                                              embedded + served at
                                              /gl/demo.vmesh (HTTP)

fixture.studioHdr ──gen_demo_hdr──▶ studio.hdr ──gl_asset_gen──▶ studio.venv
                                                                      │
                                              1,130,288 bytes; embedded + served at
                                              /gl/studio.venv (HTTP)
```

**vmesh v3**: stride-48 vertices (pos f32x3, normal f32x3, tangent f32x4
w/ handedness, uv f32x2). Submesh records are 72 bytes: index range,
base-color RGBA factor, metallic + roughness, emissive RGB, occlusion
strength, and five texture indices (all always ≥ 0; missing textures
baked as neutral 1×1 inline). Version check in `vmesh.Reader` hard-rejects
v1/v2 files. `gl_asset_gen` generates tangents at build time when the `.glb`
lacks a `TANGENT` attribute (`tangent.zig`, MikkTSpace-compatible algorithm).
gltf.zig parses full `pbrMetallicRoughness` + normal/emissive/occlusion
maps; mesh/node names are extracted (fallback: `"mesh{n}"`) and stored in
the name table; `texCoord != 0` returns `error.Unsupported`.

**vmesh v3 header** (56 bytes, all integers little-endian u32):

| Offset | Field | Notes |
|--------|-------|-------|
| 0 | magic `"VMSH"` | 4 bytes |
| 4 | version = 3 | |
| 8 | vertex_count | |
| 12 | index_count | |
| 16 | submesh_count | |
| 20 | texture_count | |
| 24 | vertex_off | 16-aligned from file start |
| 28 | index_off | 4-aligned |
| 32 | tex_table_off | |
| 36 | tex_data_off | 4-aligned |
| 40 | bvh_off | 16-aligned; 0 iff bvh_node_count == 0 |
| 44 | bvh_node_count | |
| 48 | name_table_off | 4-aligned; 0 iff name_count == 0 |
| 52 | name_count | |

**BVH section** @ `bvh_off`: `bvh_node_count × 32` bytes (flat array of
`bvh.Node`, format frozen):

```
aabb_min  f32×3 @0
aabb_max  f32×3 @12
left_or_first u32 @24   (interior → left child index; leaf → first tri_perm index)
count     u32 @28       (0 = interior; >0 = leaf, triangle count)
```

Immediately follows: `tri_perm` — `u32 × (index_count/3)` triangle
permutation indices (4-aligned automatically after the node array).

**Name-table section** @ `name_table_off`: `name_count × 12` bytes, then
a name blob. Each 12-byte entry: `name_hash u32` (FNV-1a-32) @0,
`blob_off u32` (absolute file offset) @4, `blob_len u32` @8. Entry
index maps 1:1 to submesh index; `name_count == submesh_count` when
present, 0 when absent.

**`.venv` format**: prefiltered IBL environment — RGBA16F only (no RGBA8
fallback; WebGL2 core guarantees half-float upload and filtering; the
prefilter is build-time so no in-browser fallback is needed). Three
sections: irradiance cubemap (32² × 6 faces), specular cubemap (128² × 6
faces × 6 mip levels, roughness 0.0–1.0), and a BRDF split-sum LUT (64²
RG16F). `venv.Reader` is freestanding-safe, allocation-free, and
hostile-hardened (same pattern as vmesh). IBL prefilter runs at build
time via `ibl.zig` (importance-sampled GGX + cosine-weighted irradiance);
typical build cost is ~3.6 s for the studio environment. The
**`-Dgl-ibl-fast`** build flag (P8) lowers the prefilter sample counts
(irradiance 128→32, specular 64→16, BRDF LUT 256→64) for a markedly
faster build at reduced lighting quality — the `.venv` output sizes (and
thus the format) are unchanged, only the prefiltered values are coarser.

`.vmesh` is a zero-parse format: the runtime fetches the file, drops it
into linear memory, and points `CREATE_BUFFER`/`CREATE_TEXTURE` records
straight at the bytes. `bvh.nodesFromBytes` / `triPermFromBytes`
reinterpret the BVH section in place (no allocation). The reader
(`vmesh.Reader`) is freestanding-safe, allocation-free, and hardened
against hostile headers (all size math u64-widened; truncation and
overflow return errors, never panic). The glb parser and PNG decoder are
similarly defensive — `gl_asset_gen` fails the build loudly.

glTF support today: static meshes, multiple primitives/materials, full
pbrMetallicRoughness (base-color/metallic-roughness/normal/emissive/
occlusion), mesh/node names, **node transforms (baked — P8)**, u16 indices,
f32 attributes. Node TRS/`matrix` is composed down the scene-graph hierarchy
and baked into vertex pos/normal/tangent at parse time (first node referencing
a mesh wins — no instancing). Deferred: skinning/morph, Draco/meshopt, KTX2,
JPEG (convert to PNG before importing).

**Asset region ownership**: runtime `.vmesh` and `.venv` files land in a
dedicated 4 MB page-scoped bump region (`src/client/asset_region.zig`,
`verve_asset_alloc` / `verve_asset_reset` / `verve_asset_used`). The
bridge `gl_load` fetches into this region. Asset bytes remain valid for
the page lifetime, so `Registry` records can safely store pointers into
them for context-restore replay. The chunk arena (`verve_chunk_alloc`)
remains for smaller runtime data (256 KB total); large asset files use
the asset region exclusively.

## Driving a canvas from an island

### Declarative: `ctx.glScene`

The highest-level surface. SSR a fully interactive 3D scene with orbit
camera, BVH ray-picking, and poster swap in a single fluent call:

```zig
const scene = try ctx.glScene(.{
    .src    = "/gl/demo.vmesh",
    .env    = "/gl/studio.venv",
    .poster = "/gl/poster.webp", // optional — shown until first frame
})
    .camera(.{ .distance = 4, .pitch = 0.3, .yaw = 0 })
    .light(.{ .dir = .{ -0.4, -0.7, -0.6 }, .intensity = 3 })
    .autoRotate(0.3)              // rad/s; off under prefers-reduced-motion
    .onPick("Cube", cube_click_id)
    .onPick("Sphere", sphere_click_id)
    .build();
```

`ctx.glScene` returns a `*GlSceneBuilder`; every setter returns
`*GlSceneBuilder` for chaining; `.build()` returns `*verve.Node` (or a
poison node on error). Up to 4 pick registrations are supported (shared
budget across both forms); `name` is matched against vmesh submesh names at
runtime (FNV-1a-32 hash, then string compare):

- `.onPick(name, closure_id)` fires `dispatchEvent(closure_id)` (a runtime
  event slot — the SSR-registered closure) on a hit.
- `.onPickExport(name, event_name)` (P8) dispatches a bubbling DOM
  `CustomEvent(event_name, { detail: { name } })` from the canvas on a hit —
  no closure id needed; any page JS can `addEventListener(event_name, …)`.
  Both forms may target the same mesh; the first matching slot wins.

`.build()` emits a `<div style="position:relative">` wrapper containing
a `<canvas data-ref="glscene-canvas">` wired with `z-on-pointerdown/
pointermove/pointerup/wheel/click` handlers, and — when `poster` is
provided — an `<img data-gl-poster>` positioned absolutely over the
canvas. The whole subtree is wrapped in the `GlScene` island marker;
the `GlScene` chunk hydrates it.

### Imperative: manual island + frame export

The lower-level surface (the `/gl` route reference implementation):
SSR a `<canvas data-ref="...">` inside an island, and in the chunk:

```zig
const verve = @import("verve");
const gl = verve.gl;

extern "verve" fn gl_start(ref_handle: i32, name_ptr: [*]const u8, name_len: u32) void;

export fn hydrate(_: u32, _: u32, _: u32) void {
    if (verve.queryRef(@as([]const u8, "my-canvas"))) |h|
        gl_start(h, "my_frame".ptr, "my_frame".len);
}

export fn my_frame(dt_ms: f32, width: u32, height: u32) u32 {
    // mutate scene, updateWorld(), encode commands…
    // return a pointer to the length-prefixed stream; 0 stops the loop.
}
```

The bridge owns the rAF loop, dpr-aware canvas sizing, and context
setup; a faulting stream stops the loop with a console error instead of
dying silently. WebGL2-less environments log and leave the canvas
inert (SSR content stands).

**One stateful gl island per page.** Island chunks share the main
client's linear memory, and every chunk links its static data at the
same base address — two chunks with mutable statics on one page clobber
each other (see the islands guide). `GlScene` and `GlDemo` must live on
separate routes for this reason. A framework-level fix (per-chunk data
regions) is on the roadmap.

## P3 — PBR, IBL, vmesh v2

**Command tags 10–13** are the P3 additions to the frozen wire contract:

- `CREATE_TEXTURE_EX` (10): uploads a prefiltered cubemap. Payload carries
  face count, mip levels, width/height, and `(ptr, len)` into the asset
  region. The bridge sets `TEXTURE_MAX_LEVEL` to the mip count and never
  calls `generateMipmap` — mips are precomputed in `.venv`.
- `SET_LIGHTS` (11): packs up to 4 directional or point lights into the
  frame; each entry is 8 f32 (type, position XYZ, color RGB, intensity).
- `BIND_IBL` (12): binds the three IBL textures (irradiance / specular /
  BRDF LUT) by handle.
- `DRAW_PBR` (13): draw call that reads the material block (12 f32) and
  dispatches the PBR über-shader. Texture handles for the five material
  maps are packed into the payload.

Bridge texture records carry `{tex, target}` pairs so cubemaps and 2D
textures use distinct GL targets through the same handle namespace.

**Deferred** (recorded for v1.x planning): ~~sRGB internal formats
(`SRGB8_ALPHA8`)~~ (shipped P8); ~~prefilter quality flag (`-Dgl-ibl-fast`)~~ (shipped P8); per-submesh
shader-variant selection; shadow maps; hostile vmesh tex-index validation
(current mitigation: clamp in the island `texHandle` helper).

## P4 — orbit controls, BVH picking, declarative scene

### Orbit camera (`src/core/gl/orbit.zig`)

`Orbit` is a damped spherical-coordinate camera controller. State:
`target Vec3`, `distance`, `yaw`, `pitch` (all with min/max clamps);
velocity fields `vel_yaw / vel_pitch / vel_dist`; `damping f32`
(per-second exponential approach rate, default 12.0).

```zig
pub fn tick(self: *Orbit, dt_ms: f32, input: OrbitInput) void;
pub fn eye(self: *const Orbit) math.Vec3;
pub fn viewMatrix(self: *const Orbit, up: math.Vec3) math.Mat4;
```

Integration model (frame-rate independent):

```
vel += input.delta              — inject impulse once per tick
a    = 1 − exp(−k · dt_s)      — exponential approach factor
pos += vel · a                  — apply fraction of remaining velocity
vel *= (1 − a)                  — decay remainder
```

`autoRotate` (in `GlScene`) bypasses damping: `orbit.yaw += rate*dt_s`
is applied before `tick()`, giving a constant angular rate. User drag
impulses still flow through `tick()` normally.

### Pick ray + triangle intersection (`src/core/gl/ray.zig`)

```zig
pub fn rayFromCamera(
    eye: math.Vec3, target: math.Vec3, up: math.Vec3,
    fov_y: f32, aspect: f32, ndc_x: f32, ndc_y: f32,
) Ray;

pub fn intersectTriangle(ray: Ray, v0: math.Vec3, v1: math.Vec3, v2: math.Vec3) ?f32;
```

`rayFromCamera` builds the camera basis analytically — no matrix
inverse required. NDC `(ndc_x, ndc_y)` ∈ [−1, 1]², y-up convention.
`intersectTriangle` uses Möller–Trumbore; returns `t > epsilon` of the
nearest hit or `null`. No backface culling.

### BVH (`src/core/gl/bvh.zig`)

Flat array of 32-byte nodes (format above). Build (`bvh.build`) is
native-only (allocates, median split). Walk (`bvh.walk`) is freestanding:
fixed `[max_depth]u32` stack, no allocation — safe in wasm.

```zig
pub fn build(alloc: std.mem.Allocator, positions: []const f32,
             stride_f32: u32, indices: []const u16) !BuildResult;

pub fn walk(nodes: []const Node, tri_perm: []const u32,
            positions: []const f32, stride_f32: u32,
            indices: []const u16, r: ray.Ray) ?Hit;

pub fn nodesFromBytes(bytes: []const u8) []const Node;
pub fn triPermFromBytes(bytes: []const u8) []const u32;
```

`Hit.tri_index` is the original (pre-permutation) triangle index.
`gl_asset_gen` runs `bvh.build` at build time and writes the result into
the vmesh v3 BVH section; the client chunk calls `bvh.nodesFromBytes` to
get a zero-alloc node slice from the fetched asset bytes.

### GPU resource registry (`src/core/gl/registry.zig`)

`Registry(cap)` is a comptime fixed-capacity record log (freestanding,
no allocation). Call `record*` as you issue `CREATE_*` commands; on
WebGL context restore, call `replay` to re-emit all resource uploads:

```zig
pub fn recordBuffer(self: *Self, handle, kind, ptr, byte_len) void;
pub fn recordShader(self: *Self, handle, variant, vs_ptr, vs_len, fs_ptr, fs_len) void;
pub fn recordTexture(self: *Self, handle, width, height, ptr, byte_len) void;
pub fn recordTextureEx(self: *Self, handle, target, format, width, height, mip_count, ptr, byte_len) void;

pub fn replay(self: *const Self, enc: *command.Encoder) void;
pub fn count(self: *const Self) usize;
pub fn overflowed(self: *const Self) bool; // true if cap exhausted (warn on restore)
```

Records store raw pointers; asset-region bytes remain valid for the page
lifetime, so recorded pointers are safe to replay after context loss.

### GPU lifecycle management

**Island unmount**: the bridge calls `disposeGlState` when a gl island's
canvas leaves the DOM (`canvas.isConnected` check). This sends
`DELETE_RESOURCE` for every active handle and stops the rAF loop.

**Frame returns 0**: the chunk signals it is done by returning 0 from the
frame export. The bridge stops the loop and calls `disposeGlState`.

**WebGL context lost/restored**: the bridge listens for
`webglcontextlost` (calls `preventDefault`, stops the rAF loop) and
`webglcontextrestored` (resets all handle arrays, calls
`<frame_export>_restore`, resumes the loop). On restore, `GlScene`
exports `glscene_frame_restore()` which sets `needs_replay`; the next
frame calls `registry.replay(&enc)` to re-upload all GPU resources
without re-recording. `GlDemo` exports `gldemo_frame_restore()` which
clears its `resources_sent` flag, re-running the create block.

**Poster swap**: the bridge hides `img[data-gl-poster]` on the first
non-empty `interpret()` call. On context loss or when WebGL2 is
unavailable, the poster is restored (or the canvas background shows).

### `GlScene` island chunk (`src/client/islands/GlScene.zig`)

`GlScene` is the wasm chunk that hydrates `ctx.glScene` output. Key
design choices:

- **Model identity; camera orbits.** MVP = proj · view · identity. The
  normal matrix is identity-9. The pick ray operates directly in world
  (= model) space — no world→local inverse needed. `autoRotate` spins the
  camera yaw, not the mesh, so picking stays coherent at every angle.
  (**Superseded in P6**: a per-submesh scene graph replaces model
  identity, and picking inverse-transforms the ray into each node's
  local space — see the P6 section.)
- **Drag signs.** Dragging right moves the camera left (yaw decreases):
  `dyaw -= dx * sens`. Scroll down zooms out: `dzoom += deltaY * zoom_sens`.
- **Hover.** One raycast per frame while not dragging. Stamps
  `data-gl-hover` on the canvas with the hovered submesh name (or removes
  it on miss).
- **Pick dispatch.** Click triggers a raycast; the hit submesh name is
  matched against `pick_names[i]` (hash then string compare). On match,
  fires `dispatchEvent(pick_event_ids[i])`, running the SSR-registered
  closure in the island's vid context.
- **Context restore.** Create block runs exactly once (`resources_sent`).
  Every `create*` call is mirrored into a `Registry`. On restore the
  bridge calls `glscene_frame_restore`; the next frame emits
  `registry.replay(&enc)` then resumes normal frames. Recorded pointers
  into the asset region remain valid.

### `/gl-scene` demo route

The `/gl-scene` route (`src/app/routes.zig`) is the declarative demo:
`ctx.glScene` with orbit camera, auto-rotate, and click-picking. Compare
with `/gl` (imperative `GlDemo` chunk). Both can be visited in the same
browser tab without conflict because they are separate routes (separate
page loads), satisfying the one-stateful-chunk-per-page constraint.

## P5 — verve.anim integration (gl-target tweens + scroll scrub)

P5 connects `verve.anim` to the gl scene so any animatable property
(camera orbit, material coefficients, model rotation) is driveable by a
tween, timeline, or scroll-scrubbed timeline — no custom update loop.

### gl-target prop kind and wire format

A new `glTarget` prop kind is added to the anim wire format
(`src/core/anim/serialize.zig`). The serialized **key** is
`"@gl:<target_id-decimal>"` (e.g. `"@gl:16777473"`). The **value
object** carries:

```json
{"gl": 16777473, "gls": 7, "to": 0.8}
```

| Field | Type | Meaning |
|-------|------|---------|
| `gl` | u32 | target id (frozen encoding below) |
| `gls` | u32 | setter slot (returned by `animGlSetter`) |
| `to` | f64 | destination value |
| `f` | f64 | (optional) from value; defaults to 0 when absent |

The `@gl` prefix lets the bridge `animWriteProp` function identify
gl-target props at a glance and route them through the setter indirect
table instead of any DOM write. Reverse tweens (`glTargetFrom`) swap
`to` and `f`. The non-gl output is byte-identical to pre-P5 (frozen
regression test in `serialize.zig`).

### Target-id encoding (`src/core/gl/anim_target.zig`)

Target ids are 32-bit integers with a frozen bit layout:

```
bits [31:24]  kind     (0 = camera, 1 = material, 2 = model)
bits [23:8]   submesh  (material only; 0 for camera/model)
bits [7:0]    field
```

Fields per kind:

| Kind | Field | Value |
|------|-------|-------|
| camera (0) | yaw | 0 |
| camera (0) | pitch | 1 |
| camera (0) | distance | 2 |
| material (1) | metallic | 0 |
| material (1) | roughness | 1 |
| model (2) | yaw | 0 |

**Path grammar** — resolve once at setup via `anim_target.resolvePath`:

```
"camera.yaw"  |  "camera.pitch"  |  "camera.distance"
"material:<Name>.metallic"  |  "material:<Name>.roughness"
"model.yaw"
```

> **Note:** Additional material fields (emissive RGB, base-color RGB) and node fields (rotation/translate/scale) were added in later phases — see the P6 and post-P6 tables below.

`<Name>` is matched against the vmesh v3 name table (FNV-1a-32 hash,
then string compare) — requires the asset to be loaded. Material submesh
index is baked into the target id at resolution time so runtime dispatch
is a single decode + array write.

### Tween builders (`src/core/anim/tween.zig`)

Three new builder methods on `TweenBuilder`:

```zig
// tween to a gl scene property
pub fn glTarget(self: *Self, id: u32, setter_slot: u32, to: f64) *Self;
// tween from a value to the current gl property (reverse)
pub fn glTargetFrom(self: *Self, id: u32, setter_slot: u32, from: f64) *Self;
// tween from an explicit from to to
pub fn glTargetRange(self: *Self, id: u32, setter_slot: u32, from: f64, to: f64) *Self;
```

`"@gl"` is a reserved name — passing it as a CSS selector to a regular
`to(selector)` call is a build error. These builders are **island-only**
(the setter slot is resolved at chunk hydration time, like dynamic
values); they serialize as `error.GlTargetNotIsland` if called on the
SSR surface.

### Setter registration (`src/client/island_runtime.zig`)

Island chunks register a setter callback once (typically in `hydrate`)
and receive a slot that is later embedded into the tween descriptor:

```zig
// Register fn(target_id: u32, value: f64) void; returns setter slot.
pub fn animGlSetter(f: *const fn (u32, f64) void) u32;
```

The returned slot is the index into the bridge's indirect setter table
(`verve_anim_register_setter` JS import). The `GlScene` chunk registers
`glscene_anim_set` (which decodes the target id and writes the
appropriate orbit/material-pool/model_yaw static), then embeds the slot
into timeline descriptors built in `vmesh_ready`.

### JS engine (`src/bridge/verve.js`)

`animWriteProp` branches on `name.startsWith("@gl")`:
1. Interpolate the value with the tween's easing and any modifiers.
2. Call `indirectTable.get(gls)(gl, value)` — the registered setter.
3. **Return before any DOM write** — gl props never touch the DOM.

`from` defaults to 0 when the `"f"` field is absent from the wire
object (gl props have no DOM-readable current value). `verve_anim_register_setter` is the JS import that the bridge exposes to island
chunks; it mirrors the `dyn`/`mod` registration mechanism.

### Separate rAF loops (deviation from spec)

The spec called for a shared anim+gl tick. P5 keeps **separate rAF
loops**: the anim engine writes gl statics on its own tick; the gl
engine reads those statics on the next frame. This introduces at most
one frame of lag (~16 ms at 60 fps). The deviation is recorded here;
a shared-tick pass is deferred (see below).

### `GlScene` scroll-scrub demo

When `ctx.glScene(...).scrub(true)` is set, the `/gl-scene` route
renders an island-internal 300 vh section with a sticky 100 vh viewport
and an aspect-ratio canvas box. A scroll-scrubbed timeline is built in
`vmesh_ready` (after the asset is loaded and submesh names are
resolved):

- **Turntable**: `camera.yaw` from current → current + 2π (full
  rotation). The camera orbits; the model itself stays fixed in P5.
  (P6 also drives per-node `model` rotation — see the P6 demo below.)
- **Material roughness**: `material:Cube.roughness` from 0.045 → 1.0
- **Trigger**: `ScrollTrigger` over the island-internal section `<div>`
  with `smooth: 0.4` scrub

`autoRotate` is zeroed when `scrub` is true (the scroll owns rotation).
The scrub prop is a positional bump in the Props struct; all three
`GlScene` mirrors (SSR builder, island hydrate decoder, vmesh_ready)
are kept in sync.

### SSR `material:`/`node:` targets (deferred name resolution)

`camera.*` and `model.*` resolve to a frozen target id **without** a
vmesh `Reader` (`resolvePathStatic`), so SSR can declare them directly.
`material:<Name>.*` and `node:<Name>.*` need the name table, which only
exists on the client — so SSR uses **deferred resolution**:

```zig
// comptime-pure: {kind, field, name_hash} — no Reader needed
const m = comptime verve.gl.anim_target.resolvePathStaticDeferred("material:Cube.metallic").?;
const placeholder = comptime verve.gl.anim_target.encode(m.kind, 0, m.field); // submesh bits 0
_ = tween.glTargetRangeHashed(placeholder, m.name_hash, 0, 0.0, 1.0);
```

`resolvePathStaticDeferred` parses the field and computes the FNV-1a-32
`name_hash` (both pure/comptime); the submesh **index** is resolved on
the client. The hashed builders (`glTargetHashed` / `glTargetFromHashed`
/ `glTargetRangeHashed`) carry the hash, and `serialize.zig` emits it as
a numeric `"gh"` wire field — **only when `name_hash != 0`**, so already
-resolved tweens (camera/model/indexed) stay byte-identical to before.

On the first animation tick the bridge calls the chunk's registered
resolver (`animGlResolver` → `glscene_resolve_target`), which maps
`name_hash → submesh index` via `Reader.findName` and re-encodes a
frozen id, caches it (`st.gl = real; st.gh = 0`), then applies through
the existing setter path. An unresolved target (mesh not loaded, name
absent, or no resolver yet) drops the write and retries next tick —
never crashes. The `/gl-scene` demo drives `material:Cube.metallic`,
`node:Cube.rotationY`, `node:Cube.translateY`, and `node:Cube.scaleX`
from SSR this way (disjoint from the island's own scrub timeline; the
island owns yaw/roughness/rotationX/emissiveR). Translate/scale writes
are absolute overwrites each frame; non-uniform scale makes cross-node
pick `t` approximate (see the node-field table above).

### Deferred

All five P5 deferrals below shipped in **P6** (see the P6 section):

- **Shared rAF tick** — ✅ P6. Single `requestAnimationFrame` drives the
  anim engine then every gl frame sink, eliminating the ≤1-frame lag.
- **`node:<Name>.rotation` paths** — ✅ P6 (`node:<Name>.rotationX|Y|Z`).
- **Emissive tween paths** — ✅ P6 (`material:<Name>.emissive{R,G,B}`).
- **SSR-side glTarget** — ✅ P6 for `camera.*` / `model.*` via
  `resolvePathStatic` (slot-0 page-default setter). `material:` / `node:`
  paths stay island-only (they need the runtime name table).
- **model.yaw + hover coherence** — ✅ P6. Per-node inverse-transform
  picking (`bvh.walkRange` + `transformRay`) now covers arbitrary rigid
  per-node rotations, not just `model.yaw`.

Still deferred past P6: per-node AABB / frustum culling (P9);
multi-instance stateful gl islands per page (P7).

## P6 — anim completion + node transform stack

P6 finishes the verve.anim ↔ gl bridge and replaces the P5 single-yaw
model with a real per-submesh scene graph. The headline wins: per-node
rotation and emissive properties are now animatable; gl tweens can be
authored **server-side** for camera/model paths; and the anim and gl
engines now share **one** requestAnimationFrame, so an anim setter write
lands in the *same* visual frame the gl engine reads it (the P5
≤1-frame lag is gone).

### Math: inverse + point/dir transforms (`src/core/gl/math.zig`)

`Mat4.invert` is a full 4×4 cofactor inverse (the last v1.x math
deferral, now shipped). Two companion helpers apply a matrix to a
vector with an implied homogeneous w:

```zig
pub fn invert(m: Mat4) Mat4;                       // general 4×4 inverse
pub fn transformPoint(m: Mat4, v: Vec3) Vec3;      // w = 1 (translation applies)
pub fn transformDir(m: Mat4, v: Vec3) Vec3;        // w = 0 (translation ignored)
```

`ray.transformRay(r, m)` (`src/core/gl/ray.zig`) transforms a ray:
origin as a point, direction as a vector. The direction is **not**
renormalized — for rigid transforms (rotation + translation, unit
scale) the Möller–Trumbore parameter `t` stays comparable across
differently-transformed rays, which is exactly what per-node picking
needs (a global nearest-`t` across nodes is meaningful). This is the
primitive behind inverse-transform picking below.

### New target-id kinds + fields (`src/core/gl/anim_target.zig`)

The frozen bit layout is unchanged (`[31:24]` kind | `[23:8]` submesh |
`[7:0]` field) — pre-P6 ids are byte-identical, regression-locked. P6
adds one kind and three material fields; the node translate/scale fields
were added post-P6 (append-only, ids frozen):

| Kind | Field | Value | New in |
|------|-------|-------|--------|
| camera (0) | yaw / pitch / distance | 0 / 1 / 2 | P5 |
| material (1) | metallic / roughness | 0 / 1 | P5 |
| material (1) | **emissiveR / G / B** | **2 / 3 / 4** | **P6** |
| material (1) | **baseColorR / G / B** | **5 / 6 / 7** | **post-P6** |
| material (1) | **baseColorA** | **8** | **post-P6** |
| model (2) | yaw | 0 | P5 |
| **node (3)** | **rotationX / Y / Z** | **0 / 1 / 2** | **P6** |
| **node (3)** | **translateX / Y / Z** | **3 / 4 / 5** | **post-P6** |
| **node (3)** | **scaleX / Y / Z** | **6 / 7 / 8** | **post-P6** |

For `node`, the submesh bits carry the vmesh submesh index (same
encoding `material` already used). Path grammar:

```
"node:<Name>.rotationX"   |  "node:<Name>.rotationY"   |  "node:<Name>.rotationZ"
"node:<Name>.translateX"  |  "node:<Name>.translateY"  |  "node:<Name>.translateZ"
"node:<Name>.scaleX"      |  "node:<Name>.scaleY"      |  "node:<Name>.scaleZ"
"material:<Name>.emissiveR"  |  "material:<Name>.emissiveG"  |  "material:<Name>.emissiveB"
"material:<Name>.baseColorR"  |  "material:<Name>.baseColorG"  |  "material:<Name>.baseColorB"
"material:<Name>.baseColorA"
```

`baseColorR/G/B` (ids `0x01000005`–`07`, field values 5–7) are **multipliers on the
textured albedo** — the runtime writes directly into `mats[s][0..2]` (the base-color
RGB factors streamed to `draw_pbr` each frame). Values range 0.0–1.0 (clamped by
the shader).

`baseColorA` (id `0x01000008`, field value 8) is the **per-submesh alpha factor**:
the runtime writes `mats[s][3]` which is passed to the shader as the blend alpha.
Effective only for submeshes whose vmesh `alpha_mode == 1` (BLEND) — see
[Transparency (alpha-blend)](#transparency-alpha-blend) below. Values range 0.0–1.0.

These are frozen append-only ids; pre-existing ids (`metallic`/`roughness`/`emissive*`/`baseColor*`) are
byte-identical.

Translate/scale writes are **absolute overwrites** of the node's
position/scale each frame (not deltas); they compose with the existing
rotation. Non-uniform scale (different X/Y/Z values) makes the
`t`-parameter comparison in cross-node BVH picking approximate — the
nearest-hit is still correct for axis-aligned picks but may be off for
heavily non-uniform nodes.

`resolvePath(reader, path)` resolves all kinds (the `<Name>` lookup
needs the vmesh name table). **`resolvePathStatic(path)`** is a
reader-free resolver for SSR: it handles **only** `camera.*` and
`model.*` (no name table required) and returns null for `material:` /
`node:` / unknowns. Use `resolvePathStaticDeferred` for `material:` /
`node:` paths from SSR — see the deferred-resolution subsection below.

### Optional `gls` on the wire (`src/core/anim/serialize.zig`)

The `@gl:<id>` value object now emits `"gls"` (the setter slot) **only
when it is non-zero**. Slot `0` is reserved to mean "page-default
setter" — the bridge resolves it at write time (below). Existing gl and
non-gl goldens are byte-identical (slot ≠ 0 still serializes exactly as
before; the change is purely the omission of `"gls":0`).

```json
{"gl": 16777474, "gls": 7, "to": 0.6}     // explicit slot (island)
{"gl": 2, "to": 2.5}                       // slot 0 omitted → page default (SSR)
```

### Page-default gl setter (`src/bridge/verve.js`)

When a gl island calls `verve_anim_register_setter`, the returned slot
is also recorded as `defaultGlSlot` (last-wins — one stateful gl island
per page until P7). `animWriteProp` resolves `st.gls || defaultGlSlot`
at write time. If no island has hydrated yet (slot unresolved), the
write is **dropped and retried next tick** rather than throwing.

This is what makes **SSR-side glTarget** work end to end: the server
emits a slot-0 gl tween (a `glTargetRange` with `setter_slot = 0`); the
bridge binds it to the island's registered setter the moment the island
hydrates. A static page can thus carry a server-rendered scroll-scrub
camera move with no island authoring.

### Shared anim + gl rAF tick (`src/bridge/verve.js`)

P5's two separate requestAnimationFrame loops are **merged** — this
resolves the "separate rAF loops" deviation recorded in P5. A single
master ticker (the anim tick, `animTick`) runs the anim engine
**first**, then calls every registered gl frame sink (the `glSinks`
`Set`) in the same frame:

```
animTick(now):
  1. step the anim engine  → writes gl statics via the setter table
  2. for sink of glSinks: sink(now)   → gl engine reads those statics, draws
```

Because step 1 (the setter write) and step 2 (the gl read) happen in
one rAF callback, an animated property change is visible in the very
same frame — no inter-engine lag. Lifecycle: a gl canvas adds its sink
to `glSinks` on start and removes it on unmount, context-lost, and
restore (and re-adds on restore), so a dead canvas never gets ticked.

### Per-submesh scene graph (`src/client/islands/GlScene.zig`)

The P5 single `model_yaw` model-matrix is replaced by a real
`gl.Scene(max_submesh + 1)`:

- **node 0** = root `"model"` — carries `model.yaw` (a +Y rotation),
  the parent of every submesh node.
- **node s + 1** = submesh `s`, named from the vmesh name table, child
  of the root.

Per-draw world / mvp / normal matrices come from `scene.world[s + 1]`
(per-submesh matrix pools, kept distinct for stream-aliasing safety).
This is what makes per-node animation possible: a `node:<Name>.rotationX`
tween sets the Euler rotation on that submesh's node (composed Qz·Qy·Qx),
and `scene.updateWorld()` propagates it in one pre-order pass.

### Inverse-transform picking (`bvh.walkRange`)

The P5 picker assumed model identity (ray in world == model space). With
per-node rotations that no longer holds, so the pick ray is transformed
into each node's **local** space via `transformRay(r, invert(world))`.
Three paths, picked by how much is rotating:

1. **fast** — no rotation anywhere (`model_yaw == 0` and all node
   rotations identity): one BVH `walk` with the raw world-space ray
   (unchanged P5 behavior).
2. **root-only** — `model.yaw` set but every per-node rotation identity:
   one `walk` with the ray moved by `invert(world[0])` (one inverse).
3. **slow** — any per-node rotation: for each submesh `s`, move the ray
   by `invert(world[s + 1])` and **range-walk only s's triangles** via
   the new `bvh.walkRange` (a `walk` variant restricted to a contiguous
   index range), keeping a **global nearest-`t`** across all submeshes.

All transforms are rigid, so `t` is directly comparable across the
per-submesh range-walks — the global nearest wins correctly. This
replaces the old pure-Y `rotateYVec3` hack; per-node rotations now pick
and hover coherently at every angle.

`bvh.walkRange(nodes, tri_perm, positions, stride_f32, indices, r,
first_tri, tri_count)` restricts leaf triangle testing to
`[first_tri, first_tri + tri_count)` (the submesh's index range). A
nearer triangle outside the range never shadows an in-range hit
(regression-tested).

### Demo (`/gl-scene`)

The scroll-scrub timeline (built in `GlScene`'s `vmesh_ready`) now
drives four island-side properties plus six SSR-side properties:

- **`camera.yaw`** turntable — current orbit yaw → +2π (one full turn).
- **`material:Cube.roughness`** ramp — 0.045 → 1.0.
- **`node:Cube.rotationX`** wobble — −0.35 → +0.35 rad (name-gated; P6).
- **`material:Cube.emissiveR`** pulse — 0.0 → 0.6 (name-gated; P6).

Plus, built **server-side** in `components.zig` via `resolvePathStaticDeferred` +
`glTargetRangeHashed`, these **SSR `material:`/`node:` deferred targets**:

- **`camera.distance`** dolly — 4.0 → 2.5 (plain `resolvePathStatic`, slot 0).
- **`material:Cube.metallic`** — 0.0 → 1.0.
- **`node:Cube.rotationY`** — −0.6 → +0.6 rad.
- **`node:Cube.translateY`** — −0.4 → +0.4.
- **`node:Cube.scaleX`** — 0.7 → 1.3.
- **`material:Cube.baseColorR`** — 1.0 → 0.2 (multiplier on textured albedo;
  red channel dims as scroll progresses).
- **`material:Cube.baseColorA`** — 1.0 → 0.25 (alpha factor; cube fades from
  opaque to 25% opacity as scroll progresses; requires `alpha_mode=BLEND` on the
  Cube submesh — see [Transparency (alpha-blend)](#transparency-alpha-blend)).

The island timeline owns yaw/roughness/rotationX/emissiveR; the SSR tween owns
all seven server-side targets — disjoint properties, so the two anims compose
without fighting over the same setter slot.

## P8 — correctness

P8 closes recorded correctness gaps that stay inside `src/core/gl/` (no
framework memory surgery). Landed so far:

### glTF node-transform baking (`src/core/gl/gltf.zig`)

Through P6 the glTF importer flattened every mesh in **bind-pose** and silently
ignored node transforms — a mesh positioned/rotated/scaled by its node rendered
at the origin. P8 walks the node hierarchy from the active scene's roots
(`accumulateWorld`), composing `world = parent · local` (local from a node's
explicit `matrix` or its TRS via `Mat4.fromTrs`), and bakes that world matrix
into each vertex at parse time:

- **position** via `math.transformPoint` (w = 1),
- **normal** via the inverse-transpose normal matrix (`math.normalMatrix`),
  renormalized,
- **tangent xyz** via `math.transformDir`, renormalized; `w` (handedness)
  preserved.

A mesh inherits the world matrix of the **first** node that references it
(first-node-wins, matching the existing name fallback) — no instancing. A
`visited` set guards against hostile cyclic hierarchies. Identity-transform
assets (the demo cubes) are byte-unchanged.

### vmesh tex-index hardening (`src/core/gl/vmesh.zig`)

`Reader.init` now validates every submesh's five `tex_*` indices: each must be
the missing-sentinel `-1` or a real index in `[0, texture_count)`. An
out-of-range index returns the new `error.BadTexIndex` (rejected at parse)
rather than reaching the GL bind path, where the island `texHandle` clamp was
the only line of defense. The clamp stays as belt-and-suspenders.

### onPickExport — DOM CustomEvent pick dispatch (`gl_scene.zig`, `GlScene.zig`, `verve.js`)

`.onPickExport(name, event_name)` registers a pickable mesh that, on click,
dispatches a bubbling `CustomEvent(event_name, { detail: { name } })` from the
canvas (new `gl_emit_event` bridge import → `el.dispatchEvent(...)`). It shares
the `max_picks` (4) budget with `onPick` and adds a parallel `pick_export_names`
field to the frozen positional `Props` (appended last; mirrored across the three
`Props` copies). `dispatchPick` now fires the closure (`onPick`) and/or the DOM
event (`onPickExport`) for a matched slot. The `/gl-scene` demo wires the cube to
`verve:glpick`. Bridge JS has no native test harness — exercised via the route.

### sRGB internal formats (`command.zig`, `vmesh.zig`, both chunks, `verve.js`)

Base-color and emissive textures now upload with an `SRGB8_ALPHA8` internal
format so the GPU does the sRGB→linear decode on sample — the PBR shader drops
its in-shader `pow(2.2)` on those two samples (frag GLSL hashes bumped). A new
additive command tag `CREATE_TEXTURE_SRGB` (15) mirrors `CREATE_TEXTURE` (7)
but the bridge uploads with `SRGB8_ALPHA8` + generated mips (so sRGB-correct
mip filtering, unlike a post-sample `pow`). The registry gains a
`texture_srgb` record so sRGB uploads survive a context restore.

Which textures are sRGB is inferred **chunk-side** with no vmesh format change:
`vmesh.Reader.texIsSrgb(i)` returns true if texture `i` is used as a base-color
or emissive map by any submesh (metallic-roughness / normal / occlusion stay
linear). A texture used in both roles resolves to sRGB — harmless in practice
(real assets keep color and data maps distinct; the shared neutral white is
identity in either space). Both `GlScene` and `GlDemo` branch on it.

### `-Dgl-ibl-fast` prefilter-quality flag (`build.zig`, `tools/gl_asset_gen.zig`)

A `zig build -Dgl-ibl-fast` option threads a `--fast` arg to the HDR→`.venv`
asset-gen run, which selects lower IBL prefilter sample counts (irradiance
128→32, specular 64→16, BRDF LUT 256→64). Output sizes are fixed, so the
`.venv` format is byte-compatible — only the prefiltered values are coarser.
Measured ~3.4× faster prefilter on the studio environment; default builds are
unchanged (full quality).

slice 1; per-node AABB / frustum culling in slice 2; directional shadow map in

## P9 — render quality

### Slice 1 — per-submesh shader-variant selection

**Writer change (`src/core/gl/gltf.zig`).** The glTF→vmesh writer previously
neutral-baked every absent map to a 1×1 texture (white for normal, flat-normal
for normal map, etc.), leaving no signal in the vmesh to select a leaner shader.
It now emits `tex_normal = -1` when no normal map is present and
`tex_emissive = -1` when there is no emissive texture *and* the emissive factor
is zero. Base color, metallic-roughness, and occlusion maps still neutral-bake
(their samplers are always active). No vmesh format change — the 72-byte submesh
record already carried a `-1` sentinel for absent maps, and P8's
`Reader.init` validates it; the writer just uses it correctly for the two
optional slots.

**Variant derivation (`src/core/gl/vmesh.zig`).** `Reader.submeshVariant(s)`
reads a submesh's `tex_normal` and `tex_emissive` fields and returns a bitset:
`variant_pbr | (tex_normal >= 0 ? variant_normal_map : 0) | (tex_emissive >= 0 ? variant_emissive : 0)`.
Four legal combinations result (base PBR, +normal, +emissive, +both).

**GlScene fan-out (`src/core/gl/GlScene.zig`).** At scene build time `GlScene`
collects the distinct variants used across all submeshes, creates one shader per
variant (each `registry.recordShader`'d so context-restore replay works), and
stores a per-submesh variant index. The frame loop groups submeshes by variant
and calls `setPipeline` on each group switch, then immediately re-emits
`setLights` and `bindIbl` — required by the wire stream-order rule (light
uniforms and IBL uniforms must be (re-)set on the currently active program). The
runtime→comptime dispatch is an exhaustive `switch` over the four variants
(`else => unreachable`); `pbrVertexSrc`/`pbrFragmentSrc` are comptime-parametric
on `has_normal_map` / `has_emissive`.

**Bridge — no change needed.** `st.shaders[]`, `st.buffers[]`, and
`st.textures[]` are already separate handle namespaces; `SET_PIPELINE` does
`useProgram` + updates `st.active`; `SET_LIGHTS` and `BIND_IBL` set their
uniforms on the currently active program, so re-emitting them after each
pipeline switch is correct and sufficient; `BIND_TEXTURE` with handle 0 (a
`-1` map slot sentinel) is a no-op.

A submesh that carries no normal map and no emissive map now draws with the
leaner base-PBR program instead of paying for two unused samplers and their
shader terms.

### Slice 2 — per-node frustum culling

A submesh whose world-space bounding box lies fully outside the camera frustum no
longer emits a draw. Purely CPU-side and invisible to the wire contract — the
encoder just produces fewer `DRAW_PBR` records; `command.zig`'s byte and FNV
goldens are untouched.

**Culling module (`src/core/gl/cull.zig`).** `frustumPlanes(pv)` extracts the six
inward-facing, normalized frustum planes from a column-major `proj·view` matrix
(Gribb–Hartmann; the near plane uses `row3 + row2` for the WebGL `z ∈ [-1, 1]`
clip convention). `worldAabb(local, world)` transforms an AABB's eight corners and
takes their extremes (rotation-safe). `aabbInFrustum(planes, aabb)` is the
conservative positive-vertex (n-vertex) test: an AABB is culled only when its
corner farthest along some plane normal still sits behind that plane. Conservative
by design — it never culls a visible object, but may keep some that graze the
frustum edges.

**No vmesh format change.** Per-submesh model-local AABBs are computed once at asset
load in `GlScene.buildScene`, scanning each submesh's indexed positions (the same
stride-12 vertex / u16 index access the pick raycast already uses). The 72-byte
submesh record and its goldens are unchanged.

**Frame loop (`src/client/islands/GlScene.zig`).** Each frame extracts the
world-space frustum planes once from `pv`, then tests every submesh's world AABB
(`worldAabb(submesh_aabb[s], scene.world[s + 1])`) before the variant/pipeline
block. A culled submesh `continue`s before any `SET_PIPELINE` — pipeline switches
emit lazily on the first *drawn* submesh of a variant, so skipping a culled one
keeps the wire stream-order rule (SET_PIPELINE before SET_LIGHTS / BIND_IBL) intact
and elides a redundant switch. Picking and hover raycasts are independent of the
draw loop, so culled submeshes remain pickable.

#### Completion — shadow-pass culling, HUD, capacity, `/gl-cull`

The camera-pass cull above shipped in P9 slice 2. The completion adds:

- **Shadow-pass light-frustum culling.** The shadow (depth) pass previously drew
  every caster. It now extracts a second frustum from the directional light's
  `light_vp` (`frustumPlanes(light_vp)`) and skips casters whose world AABB lies
  outside the **light** frustum — not the camera frustum, so an off-camera caster
  that shadows into view still draws. Applied in both Phase A (plain depth) and
  Phase B (MASK alpha-tested depth); `depth_mvps[s]` is still computed for every
  submesh (cheap) so only the draw is elided. On scenes whose light ortho volume
  encloses all geometry (the common fit-to-scene case) this culls nothing — the
  camera-pass cull carries the visible payoff — but it prunes casters in scenes
  larger than the light volume.
- **Cull HUD.** Per-frame counters (`drawn / culled / total` for the main pass,
  plus `shadow drawn/culled`) are tallied per instance, packed by a
  `glscene_cull_stats()` export, and written to a `data-ref="glcull-hud"` overlay
  each frame by the bridge (a strict no-op on demos without that element).
- **Scene capacity.** `max_submesh` was raised 8 → 128 so dense scenes fit; the
  per-frame command buffer is sized for the 128-submesh worst case (both the main
  two-pass-blend path and the MASK shadow path). The per-chunk wasm stack was
  raised to 64 KB to accommodate the heaviest chunk (the gl frame's matrix locals
  plus the pick/hover BVH raycast recursion), and the Pass-2 transparency-sort
  scratch (`tidx`/`tkey`) moved off the frame stack into `Inst`.
- **Demo (`/gl-cull`).** A 7×7 grid of 49 unit cubes (`cubeGridGlb`), each its own
  scene node at a distinct grid position. As the camera orbits or zooms in, cubes
  outside the view frustum are skipped; the HUD shows the live drawn/culled split.
  Verified via CDP on both backends (WebGL2 + WebGPU): the culled count rises from
  0 as the camera zooms in, `drawn + culled == 49`, zero gl errors.

**Deferred:** hierarchical/subtree culling (a flat per-submesh test is ample at
this scale), GPU-side/indirect-draw culling, occlusion culling.

### Slice 3 — directional shadow map

The single directional light now casts a real depth-mapped shadow. Each frame
renders the scene twice: a depth-only pass from the light's point of view into a
depth texture, then the color pass samples that texture to darken shadowed
fragments. Additive on the wire (tags 16–20 + two shader-variant bits); the P1–P8
goldens stay byte-identical.

**Wire surface (`src/core/gl/command.zig`).** Five tags: `create_shadow_map` (FBO
+ `DEPTH_COMPONENT24` texture with `COMPARE_REF_TO_TEXTURE`), `begin_shadow_pass`
/ `end_shadow_pass` (bind/unbind the depth FBO and viewport), `draw_depth`
(position-only submesh draw, `mvp = light_vp · world`), and `bind_shadow_map`
(binds the depth texture + sets `u_light_vp`; re-emitted per pipeline switch like
`set_lights` / `bind_ibl`). Two new variant bits: `variant_shadow` (1<<5, a
shadow-receiving PBR program) and `variant_depth` (1<<6, the depth-only shader).
The shadow map binds to texture unit 8 (after the IBL units 5–7).

**Shaders.** A dedicated depth shader (`depthVertexSrc` / `depthFragmentSrc`,
position only, no color output). The PBR über-shader gains a shadow path under
`variant_shadow`: the vertex stage forwards the light-space position, and the
fragment stage runs a 3×3 PCF lookup (`sampler2DShadow`, hardware 2×2 per tap)
and attenuates the **direct** light term only — the IBL ambient stays lit so
shadowed faces don't go black. The non-shadow variant strings are byte-identical
to the pre-slice-3 source, so the existing FNV-64 GLSL hash goldens are unchanged;
new goldens freeze the shadow + depth variants.

**Bridge (`src/bridge/verve.js`).** First framebuffer-object support in the gl
interpreter: `create_shadow_map` builds an FBO with a depth-only attachment;
`begin_shadow_pass` binds it and front-face-culls (pushes self-shadow acne behind
the geometry); the color pass binds the depth texture as a comparison sampler.

**Island (`src/client/islands/GlScene.zig`).** `lightSpaceMatrix` fits an
orthographic light frustum to the union of submesh world AABBs (reusing the
slice-2 `submesh_aabb` + `cull.worldAabb`). The depth pass draws **all** submeshes
(an off-camera caster can still shadow visible geometry — no camera-frustum cull
there); the color pass keeps the slice-2 cull. The depth shader and shadow map are
recorded in the registry for context-restore replay.

**Demo (`/gl-shadow`).** A checkerboard cube on a neutral floor
(`fixture.pbrCubeFloorGlb` → `shadow.vmesh`); the cube casts a soft (3×3 PCF)
depth-mapped shadow onto the floor receiver. This is the route to screenshot when
verifying the shadow pipeline — the lone-cube `/gl-scene` has no receiver, so a
cast shadow has nothing to fall on.

## P7 — multiple GlScene instances per page

Two or more `ctx.glScene(...)` islands can now share a page, each with its own
camera, scene, picking, and animation. Demo: the `/gl-multi` route renders a model
beside a cube-on-floor, spinning opposite ways.

**The blocker.** The bridge instantiates ONE GlScene wasm chunk per page (cached
by name) and calls `hydrate(props, len, root_id)` once per
`<verve-island data-name="GlScene">` with a distinct `root_id` (the island vid).
Pre-P7 the chunk's ~51 module statics were singletons, so every instance rendered
the same shared state. (Per-canvas GL *resource* state — buffers/textures/shaders —
already lives per-canvas in the JS bridge; only the wasm state was shared.)

**Per-instance state (`GlScene.zig`).** Every per-instance static moved into an
`Inst` struct; `instances[MAX_INSTANCES=4]` is keyed by vid (`findSlot`/`allocSlot`,
`Inst{}` is the fresh-hydrate reset). The draw pools live inside `Inst` in the fixed
array, so `&inst.mvps[s]` stays a stable absolute address for the stream-aliasing
contract. `cmd_buf` stays a single shared transient (the bridge walks each frame's
stream before the next; instances never interleave within a tick).

**Routing — `glscene_select(root_id)`.** A new chunk export sets a `current: ?*Inst`
pointer; the bridge calls it before every frame / event / asset-callback / restore
dispatch, deriving the vid from the canvas's enclosing `<verve-island data-vid>` (or
the in-flight hydrate's vid, captured for async `gl_load` callbacks). All other
exports keep their signatures and operate on `current`, so the generic gl-driving
contract is frozen — GlDemo and non-gl islands make the bridge's guarded select a
no-op. Anim scoping uses a comptime per-slot trampoline table (no `anim_target`
format change); `glscene_unmount(root_id)` reclaims a slot on canvas disconnect.

**Asset region.** The 4 MB page-scoped bump region (`asset_region.zig`) is now reset
only when the FIRST instance of a fresh population hydrates (`live_count` 0→1) —
instances SHARE it while ≥1 is live, and a full unmount→remount re-resets. N large
scenes share 4 MB (raise `region_capacity` if needed; `alloc` degrades gracefully).

Still ONE instance-of-chunk: co-locating a DIFFERENT stateful chunk (GlDemo) on the
same page still overlaps at data base `0x1000` — that's the separate memory-partition
track, deferred.

## P10 — WebGPU backend

A SECOND GPU backend over the SAME frozen binary command stream. The wire
contract (`command.zig`) is unchanged; a parallel JS interpreter drives WebGPU
instead of WebGL2, and shaders are generated as WGSL in Zig alongside the GLSL.

### Slice 1 — minimal unlit-cube bring-up (shipped)

Proves the second backend end-to-end with the smallest scene — an unlit
vertex-color cube rendering on a real WebGPU device (`/gl-webgpu`).

- **WGSL in Zig (`command.zig`).** `pub const wgslUnlit` is the unlit
  vertex-color shader as a single WGSL module (`@vertex vs_main` + `@fragment
  fs_main`, `mvp` uniform at `@group(0)@binding(0)`), mirroring the GLSL
  `unlit_vs`/`unlit_fs`. Frozen by its own FNV-1a-64 golden; the GLSL byte + hash
  goldens are untouched. No wire-format change — the chunk simply puts WGSL in
  `create_shader`'s `vs` slot (fs slot 0) when targeting WebGPU.
- **WebGPU interpreter (`verve.js`).** `gpuInit(canvas)` (adapter→device→
  configure, returns null + degrades gracefully when WebGPU is absent);
  `gpuInterpret(st, ptr)` walks the same stream as `glInterpret` and maps the
  minimal subset to WebGPU: `begin_frame` → command encoder + render pass (+ a
  `depth24plus` depth texture, recreated on resize); `create_buffer` →
  `createBuffer`+`writeBuffer`; `create_shader` → `createShaderModule` +
  `createRenderPipeline` (the pipeline bundles the stride-24 vertex layout +
  format + depth state, since WebGPU has no global state machine);
  `set_pipeline`/`draw` (mvp uniform buffer + bind group, `drawIndexed`)/
  `end_frame` (submit). Unknown tags size-skip. `gpuStart(ref, export)` is the
  WebGPU frame loop (parallel to `glStart`, shares the master rAF `glSinks`),
  reached by a new `gl_start_gpu` chunk import.
- **Demo (`/gl-webgpu`).** `GlWebgpu.zig` uploads the shared `mesh.zig` unlit
  cube + `wgslUnlit`, then `gl_start_gpu`. Verified: the cube renders headless
  (Chrome `--enable-unsafe-webgpu --use-angle=metal`), zero console errors.
- **Isolation.** Purely additive; the WebGL2 path (`glStart`/`glInterpret`/
  `gl_start`) and the GLSL goldens are untouched, so `/gl*` cannot regress.

### Slice 2a — textured, direct-lit PBR (shipped)

A textured Cook-Torrance PBR cube under a direct directional light, rendered
through the WebGPU backend (`/gl-scene-webgpu`), verified rendering headless.

- **WGSL PBR über-shader (`command.zig`).** `pub fn wgslPbr(flags)` is the
  parametric WGSL mirror of `pbrVertexSrc`/`pbrFragmentSrc` for the F0/F1/F2
  variants (`variant_pbr` / `+normal_map` / `+emissive`): stride-48 vertex inputs;
  a `@group(0)` uniform block (`mvp`/`model`/`normal_mat`/`camera_pos`/
  `material[3]`/`lights[8]`/…); a `@group(1)` sampler + texture bindings (slots
  0–8, normal/emissive variant-gated, cubes for IBL); full Cook-Torrance + direct
  light loop + IBL ambient + ACES tonemap. Each variant frozen by its own
  FNV-1a-64 golden; the GLSL goldens are untouched. The WGSL mirrors the *full*
  GLSL fragment (incl. the IBL term) so slice 2b adds real IBL maps without a
  shader-byte change.
- **WebGPU interpreter (`verve.js`).** `gpuInterpret` gains the material-texture
  tags — `create_texture` (7) / `create_texture_srgb` (15) →
  `createTexture`+`writeTexture` (sRGB vs linear), `bind_texture` (8) records the
  slot→handle binding. 1×1 device-default placeholder textures (white/black 2D,
  black cube) fill any unbound material/IBL slot, so the PBR bind group is always
  complete (zero IBL contribution until 2b). `create_shader` for a PBR variant
  builds the stride-48 pipeline with EXPLICIT bind-group layouts (not `"auto"`)
  matching the WGSL bindings; `set_lights` (11) packs the directional/point lights
  into the uniform buffer; `draw_pbr` (13) writes `mvp`/`model`/`normal_mat`/
  `camera_pos`/`material` at the WGSL `std140`-equivalent byte offsets, assembles
  the two bind groups, and `drawIndexed`. The JS uniform packing matches the WGSL
  struct layout byte-for-byte (16/256-byte alignment).
- **Demo (`/gl-scene-webgpu`).** `GlSceneWebgpu.zig` uploads a static stride-48
  `mesh.zig` `pbr_cube` + base-color (sRGB) and metallic-roughness textures,
  creates the F0 `wgslPbr` shader, and drives a rotating, direct-lit textured cube
  via `gl_start_gpu`. Verified rendering headless (Chrome
  `--enable-unsafe-webgpu --use-angle=metal`), zero console errors.
- **Isolation.** A dedicated WebGPU-only chunk/route; the WebGL2 path, the GLSL
  goldens, and slice-1 `/gl-webgpu` are untouched.

### Slice 2b — image-based lighting (shipped)

Real environment lighting for the WebGPU PBR path — the `/gl-scene-webgpu` cube
turns metallic and reflects a prefiltered `.venv` studio environment. **No
`command.zig` / shader change**: `wgslPbr` already declared + sampled the IBL
bindings (6 irradiance cube, 7 prefiltered cube, 8 brdf_lut, `prefiltered_mips`)
in 2a, and the 2a pipeline bind-group layout already declared 6/7 as cube /

- **WebGPU interpreter (`verve.js`).** `create_texture_ex` (10) →
  `device.createTexture` (cube = 6 array layers + a `dimension:'cube'` view;

  `writeTexture` upload (RGBA16F = 8 B/texel). `bind_ibl` (12) records the
  irr/spec/lut handles, writes `prefiltered_mips` into the uniform buffer, and
  marks the group(1) bind group dirty; `draw_pbr` then binds the real IBL views at
  bindings 6/7/8 (falling back to the black placeholders when no environment is

- **Demo (`/gl-scene-webgpu`).** `GlSceneWebgpu.zig` `gl_load`s `/gl/studio.venv`,
  and on the ready callback emits `createTextureEx` for the irradiance cube,

  material is metallic / low-roughness so the environment shows as reflections.
  Verified rendering headless (the metallic surface picks up the studio

### Slice 2c — directional shadow pass (PCF, shipped)

The `/gl-scene-webgpu` cube casts a shadow onto a ground plane. This slice DOES
touch `command.zig` (new WGSL goldens) — the non-shadow + GLSL goldens stay frozen.

- **WGSL (`command.zig`).** `wgslPbr`'s `variant_shadow` branch (the 2a
  `@compileError` lifted): a `light_vp` field appended to the uniform `U` (offset
  384, non-shadow layout unchanged), `@group(1)` bindings 9 `texture_depth_2d` + 10
  `sampler_comparison`, a `@location(5) light_pos` varying, and a `shadowFactor`
  doing 3×3 PCF with `textureSampleCompareLevel`. New `wgslDepth()` is the
  position-only depth shader for the shadow pass. Each shadow variant + the depth
  shader is FNV-golden-frozen.
- **WebGPU interpreter (`verve.js`).** `create_shadow_map` (16) → a `depth32float`
  texture + comparison sampler. `begin_shadow_pass` (17) opens a depth-only render
  pass (no color target) on the shadow map, sharing the frame's command encoder
  (it runs BEFORE `begin_frame`; one encoder, two passes, one submit). `draw_depth`
  (19) draws into it with the depth pipeline (`variant_depth` → no fragment target,
  `cullMode:'front'` for acne). `end_shadow_pass` (18) closes it. `bind_shadow_map`
  (20) records the map + caches `light_vp`; `draw_pbr` binds the depth-compare map +
  comparison sampler at group(1) 9/10 for shadow variants (1×1 default fallback).
- **Depth-clip convention.** `gl.math` ortho is GL-convention (clip z ∈ [−1,1]);
  WebGPU clips z<0 and stores depth in [0,1]. The chunk builds the light matrix as
  `Zfix · ortho · view` (Zfix row 2 = [0,0,0.5,0.5]) so the depth pass + the WGSL
  `shadowFactor` (which uses `ndc.z` directly, Y-flipped uv) agree on [0,1] z.
- **Multi-draw correctness (fix).** WebGPU defers draws, so a single shared uniform
  buffer let a later `writeBuffer` clobber earlier draws — latent in 2a/2b (one
  object/frame), exposed here (cube + plane). Each PBR + depth draw now writes its
  full uniform struct to its own 256-aligned slot and binds via a dynamic offset;
  per-frame values (lights/IBL/light_vp) are cached and replicated per slot.
- **Demo (`/gl-scene-webgpu`).** `GlSceneWebgpu.zig` adds a `mesh.zig` `pbr_plane`

### Slice 2d — shared-island backend selection (shipped; P10 complete)

## P11 — WebGPU parity

Closes the three items P10 2d deferred, bringing the WebGPU path to functional
parity with WebGL2. All bridge-side (`verve.js`) — no `command.zig` / golden change.

- **Multi-instance (`gpuStart`).** The frame loop now calls `glSelect(st.exports,
  st.vid)` (`st.vid = vidOfEl(canvas)`) before the frame export, and
  `glscene_unmount(vid)` on canvas disconnect — mirroring `glStart`. A page with
  multiple `GlScene` islands renders each instance's own state through WebGPU.
  Verified: `/gl-multi` shows two distinct scenes (a model + a cube-on-floor with a
  shadow) side by side via WebGPU.
- **`DELETE_RESOURCE` (tag 14).** `gpuInterpret` frees the named object —
  `GPUBuffer`/`GPUTexture.destroy()` for buffers/textures/shadow maps, a ref-drop +
  `st.active` clear for pipelines (GC-only in WebGPU). Parity with `glInterpret`'s
  case 14.
- **Device-loss / restore (`device.lost`).** On loss `gpuStart` stops the sink,
  shows the poster, re-inits a fresh device (+ defaults), drops ALL dead resource
  refs (no `.destroy()` — the device is gone), re-arms `device.lost` on the new
  device, and calls the chunk's `<frame>_restore` hook so its registry replays every
  create*. Graceful if re-init fails (poster stays). Best-effort + structural —
  WebGPU device loss can't be triggered headless, so this path is verified by
  review, not a live loss/restore cycle.

Deferred beyond P11: `DELETE_RESOURCE` is not yet emitted by GlScene on the WebGPU
path beyond teardown; compressed texture formats, skinning, and worker offload
remain on the gl backlog (backend-agnostic, not WebGPU-specific).

## Skinning — skeletal skinning (slice 1: static pose)

GPU vertex skinning: a rigged mesh is deformed by a skeleton of bone matrices
applied per vertex in the vertex shader. Slice 1 renders a mesh at a FIXED
(posed) skeleton on both backends; keyframe animation over time is slice 2.

- **Skinned vertex layout (stride 56).** A skinned mesh widens the PBR vertex
  from stride 48 to 56: the usual `pos f32x3 @0`, `normal f32x3 @12`,
  `tangent f32x4 @24`, `uv f32x2 @40`, plus `joints u8x4 @48` (joint indices)
  and `weights u8x4 @52` (unorm, sum 255). Non-skinned meshes are unchanged.
- **vmesh v5.** The header gains `skinned` (0/1), `skeleton_off`, `joint_count`
  (`src/core/gl/vmesh.zig`); a skeleton section stores, per joint,
  `{ parent: i32, inverse_bind: [16]f32, bind_local: [16]f32 }` (132 B each,
  column-major). `Reader.vertexStride()` / `jointCount()` / `joint(i)` read them.
- **glTF skin parse** (`gltf.zig`). `skins[0]` → joint list (node indices define
  joint order); each joint's `bind_local` from its node TRS, `inverse_bind` from
  the `inverseBindMatrices` accessor, `parent` from the node hierarchy.
  `JOINTS_0` (u8/u16) + `WEIGHTS_0` (f32) → per-vertex `[4]u8` joints + weights
  (quantized to sum 255 via largest-remainder). A glb with no skin parses
  unchanged (non-skinned path).
- **`variant_skinned = 1 << 7`.** The PBR über-shader (GLSL `pbrVertexSrc` + WGSL
  `wgslPbr`) gains a skinned branch: `a_joints`/`a_weights` attribs (loc 4/5), a
  64-entry bone-matrix palette (GLSL `uniform mat4 u_bones[64]`; WGSL a SEPARATE
  `@group(0) @binding(1)` uniform, kept out of the per-draw block so it isn't
  replicated across WebGPU dynamic-offset slots), and
  `skin = Σ wᵢ·bones[jointᵢ]` applied to position + normal. When the bit is off
  the shader bytes (and all existing goldens) are unchanged.
- **`set_bones` (wire tag 21).** `Encoder.setBones(count, ptr)` uploads the
  per-frame bone palette: WebGL2 `uniformMatrix4fv(u_bones[0], …)`; WebGPU
  `writeBuffer` into the bones uniform. The skinned pipeline binds the stride-56
  layout (joints `uint8x4`, weights `unorm8x4`) + the bones binding; the
  non-skinned pipeline is untouched.
- **`GlSkin` chunk + `/gl-skin`.** A dedicated single-instance chunk
  (`src/client/islands/GlSkin.zig`) fetches `skinbar.vmesh` (a procedural 3-joint
  rigged bar), computes a bent bone palette each frame
  (`world[j] = world[parent]·local`, mid joint carries a constant rotation;
  `bone = world·inverse_bind`), pushes it via `set_bones`, and draws the skinned
  PBR program. Backend-detects WebGPU vs WebGL2 like `GlScene`. (Note: a frame
  export must return a non-zero command buffer every frame — the WebGL2 loop
  reads a `0` return as the unmount signal — so `GlSkin` emits a clear-only frame
  until the async vmesh lands.)

Verified: `/gl-skin` renders the bar visibly BENT (upper half displaced from the
base) on BOTH backends via headless Chrome (WebGPU + forced-WebGL2), with no
console errors.

### Slice 2 — keyframe animation (looping clip)

`/gl-skin` now PLAYS a looping animation clip instead of a static pose: the bar
bends out and back over ~1 s. The skeleton + `set_bones` path from slice 1 is
reused unchanged — **no `command.zig` / shader / wire change** (all shader + wire
goldens stay byte-frozen); only the per-frame bone palette's source differs.

- **vmesh v6** (`vmesh.zig`) — header gains `anim_off: u32` at `[68..72]`
  (0 = no clip; header 68→72). An animation section (16-aligned, after the
  skeleton) holds `duration f32`, `flags u32`, a directory of `joint_count × 3`
  track entries (channel order `T=0, R=1, S=2`; each `interp u8` + `key_count u32`
  + `data_off u32`), then a data blob (per track: `key_count` times f32, then
  `key_count × comps` value f32 — `comps = 4` for rotation, else 3).
  `Reader.animPresent/animDuration/animTrack/animTime/animValue`.
- **glTF animation parse** (`gltf.zig`) — `animations[0]`: each channel
  `(joint, path∈{translation,rotation,scale}, sampler)` with `LINEAR`/`STEP`
  interpolation (`CUBICSPLINE` → `error.Unsupported`). **Every joint gets all 3
  tracks baked**: an animated channel's keys, else a single keyframe of the
  joint's bind-TRS component — so runtime sampling is uniform (no sampled-vs-bind
  mixing).
- **`Quat.slerp`** (`math.zig`) — shortest-arc quaternion interpolation (nlerp
  fallback near parallel) for rotation sampling; translation/scale use vec3 lerp.
- **`GlSkin` sampling** — each frame `t = elapsed mod duration`; per joint sample
  T (lerp), R (slerp), S (lerp) honoring each track's interp (STEP = hold) →
  `local = fromTrs(T,R,S)` → the slice-1 hierarchy walk → `bone = world ·
  inverse_bind` → `set_bones`. A skinned mesh with no clip (`anim_off == 0`) falls
  back to the static bind pose (slice-1 behavior).
- **Fixture** — `skinnedBarGlb` gains `animations[0]`: a LINEAR rotation channel
  on the mid joint (keys at 0 / 0.5 / 1 s → identity / rotZ(0.7) / identity).

Verified: two timed screenshots ~450 ms apart show the bar at DIFFERENT bend
angles (upper-half centroid shifts ~23 px) on BOTH backends, zero console errors;
all prior gl routes unchanged.

### Slice 3 — multiple clips + controls

`/gl-skin` carries MULTIPLE animation clips with runtime controls: buttons switch
clip (**Bend** / **Twist**), pause/play, and set speed (0.5× / 1× / 2×). Still
**no `command.zig` / shader / wire change** — clip selection + playback are
chunk-side state over the same `set_bones` path; goldens frozen; vmesh 6→7.

- **vmesh v7 clip table** (`vmesh.zig`) — the v6 single-clip anim section becomes
  a clip table. At `anim_off`: `clip_count u32`, `flags u32`, a clip table of
  `clip_count × 16B` (`name_hash u32` = FNV-32 of the clip name, `duration f32`,
  `dir_off u32` = offset from `anim_off` to that clip's track directory, pad),
  then per-clip sections each in the v6 layout (track directory + data blob).
  `Reader.animClipCount/animClip(i)/animTrack(clip,joint,channel)` (a 1-clip v7
  file behaves like v6).
- **glTF — all clips** (`gltf.zig`) — parses the whole `animations[]` array (not
  just `[0]`); each animation → a `vmesh.Clip` (name → `name_hash`, duration, the
  same per-joint baked T/R/S tracks as slice 2). `Model.anim_clips`.
- **`GlSkin` clip state** — module state `{cur_clip, paused, speed}`; per frame
  advances `elapsed` only when playing (`elapsed += dt·speed`) and samples the
  SELECTED clip. No-arg control exports (`glskin_clip0`/`glskin_clip1`/
  `glskin_pause`/`glskin_play`/`glskin_speed_half`/`glskin_speed_1x`/
  `glskin_speed_2x`) wired to `z-on-click` buttons (the `AnimDemo` convention) —
  events route to the chunk because the buttons live inside the island subtree.
- **Fixture** — `skinnedBarGlb` ships two clips: **Bend** (mid-joint Z rotation)
  and **Twist** (jmid + jtop Y rotation).

Verified (CDP, both backends, zero console errors): clicking **Twist** changes
the pose vs **Bend**; **Pause** freezes it (two screenshots identical); **Play**
resumes; all prior gl routes unchanged.

### Slice 4 — cross-fade blending

Clip switches now CROSS-FADE the pose old→new over 0.3 s instead of a hard cut.
Pure chunk-side — **no vmesh/gltf/fixture/shader/wire/format change** (same
`set_bones`, same buttons, same `skinbar.vmesh` v7); only `GlSkin`'s per-frame
pose composition changes during the fade window.

- **`Vec3.lerp`** (`math.zig`) — component-wise lerp; rotation blend reuses the
  slice-2 `Quat.slerp`.
- **`GlSkin` cross-fade** — on a clip switch, snapshot the OLD clip + its looped
  time (FROZEN at the switch instant) and reset a real-time fade timer
  (`fade_dur = 0.3 s`, not speed-scaled). While `fade_t < fade_dur`, each joint's
  local transform is blended at the T/R/S level — `Vec3.lerp` for translation and
  scale, `Quat.slerp` for rotation, by `w = fade_t/fade_dur` — between the frozen
  old pose and the advancing new pose, then `fromTrs` (never lerp final matrices —
  rotations would shear). Past the window it's the pure new clip. The clip-switch
  exports (`glskin_clip0`/`glskin_clip1`) now just set a pending clip applied in
  `updateBones`; pause freezes the fade too.

Verified (CDP, both backends, zero console errors): mid-fade (~60 ms after
clicking Twist) the bar's upper-half centroid sits STRICTLY between the pure-Bend
and settled-Twist positions — an intermediate blended pose; it settles to pure
Twist after the window. Steady-state playback is byte-identical to slice 3.

### Slice 5 — loop / once mode

A playback-mode toggle on `/gl-skin`: **Loop** (default) vs **Once** (play to the
end, then HOLD the last frame). Pure chunk-side — **no asset/format/shader/wire
change**; `GlSkin.zig` + the buttons only.

- A global `var loop: bool = true` in `GlSkin`. The clip sample time is
  `t = if (loop) @mod(elapsed, dur) else @min(elapsed, dur)` — in Once mode,
  past the end `elapsed > dur` sticks at `dur` and the sampler holds the final
  keyframe (frozen end pose). The slice-4 cross-fade `from_time` snapshot uses the
  same loop-aware clamp.
- Two no-arg control exports `glskin_loop` / `glskin_once`, wired to **Loop** /
  **Once** `z-on-click` buttons. Mode is independent of pause/speed/clip; default
  Loop is byte-identical to slice 4 (the clamp branch runs only in Once mode).

Verified (CDP, both backends, zero console errors): in Once mode two screenshots
~300 ms apart taken past the clip's ~1 s duration are frozen (top-half centroid
Δ≈0.1–0.4 px); in Loop mode the same late pair keeps cycling (Δ≈4 px).

### Slice 6 — scrub (drag clip time)

A scrub bar under the controls: drag it to set the current clip's time manually
(the bar poses to that frame and stays paused). Pure chunk-side + one DOM element,
reusing shipped runtime APIs — **no bridge/asset/format/shader/wire change**;
`GlSkin.zig` + the track element only.

- A track `<div data-ref="glskin-track">` with `z-on-pointerdown/move/up` →
  `glskin_scrub_down/move/up` exports (inside the island subtree so events route
  to the chunk). `touch-action:none` so touch-drag scrubs instead of scrolling.
- `glskin_scrub_down` pauses, captures the pointer (`eventCapturePointer`), and
  scrubs; `glskin_scrub_move` scrubs while dragging; `glskin_scrub_up` ends (stays
  paused). `scrubApply` reads the track's rect (`refRect`) + the pointer X
  (`eventCoordX`) → `frac = clamp((x − rect.x)/rect.w, 0, 1)` →
  `elapsed_s = frac · clip.duration`. `updateBones` is unchanged — it just samples
  `elapsed_s` (the `@mod`/`@min` are identities in `[0,dur]`).

Verified (CDP, both backends, zero console errors): dispatching a `pointerdown` at
20 % of the track then a `pointermove` to 80 % moves the bar's pose (top-half
centroid shifts with the drag); a later frame with no input is unchanged (paused
at the scrubbed frame).

### Slice 7 — clip blend (weighted Mix)

A **Mix** drag-track under the scrub bar: drag 0→100 % to blend the current clip
with the next clip (`(cur+1) % clipCount`), live, per joint. Pure chunk-side + one
DOM element; **no bridge/asset/format/shader/wire change** — `GlSkin.zig` +
`components.zig` only.

- `updateBones` is refactored to compute a per-joint BASE TRS (current clip, incl.
  the slice-4 cross-fade) as `bt/br/bs`, then — when `mix_weight > 0` and ≥2 clips
  — blend with the other clip's TRS (`Vec3.lerp` T/S, `Quat.slerp` R, by
  `mix_weight`), then one `fromTrs`. `mix_weight = 0` (default) → pure current
  (byte-identical to slice 6); `1` → the other clip; between → a weighted mix. Both
  clips sampled at the same playback time.
- A track `<div data-ref="glskin-mix">` with `z-on-pointerdown/move/up` →
  `glskin_mix_down/move/up`; `mixApply` reads `refRect` + `eventCoordX` →
  `mix_weight` (live — does NOT pause). Switching clips resets the weight.
- This is a weighted CROSS-BLEND (mix node), not true additive (which would need a
  rest-delta reference pose).

Verified (CDP, both backends, zero console errors): paused, dragging the Mix track
0 %→50 %→100 % moves the bar's top-half centroid monotonically (pure current →
blend → pure other).

### Slice 8 — ping-pong, true additive, blend masks

Three playback features, all **chunk-side** (`GlSkin.zig` + the new buttons in
`components.zig` + one pure `Quat.conjugate` helper in `gl/math.zig`) — **no
bridge/asset/format/shader/wire change**. The wire contract (`set_bones`, the
skinned PBR variant) is frozen.

- **Ping-pong.** `loop: bool` becomes `PlayMode { loop, once, pingpong }`. A single
  `clipTime(elapsed, dur)` helper maps raw playback time → clip-local time per mode
  (`.loop` = `@mod`, `.once` = `@min`, `.pingpong` = triangle wave
  `phase = @mod(elapsed, 2·dur); phase ≤ dur ? phase : 2·dur − phase`); all three
  former inline time computations (`t`, the mix `ot`, the cross-fade `from_time`)
  route through it. Button **Ping-Pong** → `glskin_pingpong`.
- **True additive.** A `blend_additive` flag (default off → byte-identical to the
  slice-7 interpolative Mix). When on, the other clip contributes its
  DELTA-FROM-ITS-OWN-REST (sampled at `t=0`) scaled by the weight, applied on top of
  the base pose: `bt += (otherₜ − other₀)·w`, `bs += (otherₜ − other₀)·w`,
  `br = slerp(identity, otherₜ · conj(other₀), w) · br`. Buttons **Mix** /
  **Additive** → `glskin_blend_mix` / `glskin_blend_add`.
- **Blend masks.** Per-joint `jw = (mask_upper and j >= 1) ? 0 : mix_weight` gates the
  blend weight in BOTH blend paths, so a masked joint holds its pure base pose. The demo
  masks the upper chain (every joint above the static root) — visibly observable: the
  articulated body stays in the current clip's pose while an unmasked blend swings it
  toward the other clip. Buttons **Mask: All** / **Mask: Upper** → `glskin_mask_all` /
  `glskin_mask_upper`.

A debug control **Freeze** / **Unfreeze** (`glskin_freeze` / `glskin_unfreeze`) stops
the camera auto-orbit and pins yaw, so an automated pose-diff between modes isolates
the skinning change without the orbit + directional-lighting confound (the bar
otherwise slowly rotates so the 3D bend reads from all sides).

Unit-tested: the ping-pong triangle wave (`0,½,1,1½,2,2½ → 0,½,1,½,0,½`) and the
`Quat.conjugate` round-trip (`q · conj(q) ≈ identity`). Verified live (headed Chrome,
forced-WebGL2, **Freeze** on, zero console errors) with a silhouette-centroid metric:
Ping-Pong reverses the pose over time; **Additive at weight 0.5 yields a pose distinct
from interpolative Mix** (centroid moves ~10 px between the two modes); **Mask: Upper
holds the articulated body** in the current pose while Mask: All blends it (large
centroid difference between the two).
(Headless WebGPU init is unavailable on this host; the slice is backend-independent —
it only edits the shared `updateBones` pose math.)

### Slice 9 — CUBICSPLINE interpolation

The last deferred skinning interpolation mode. glTF CUBICSPLINE stores **3 values per
keyframe per component** (in-tangent, point, out-tangent) and uses cubic Hermite
interpolation. End to end:

- **vmesh v8.** The per-track `interp` byte gains `2 = CUBICSPLINE` (the 12-byte directory
  entry layout is unchanged). When `interp == 2` the value blob is `key_count × 3 × comps`
  f32, laid out per key as `[inTangent(comps), point(comps), outTangent(comps)]` (else the
  v7 `key_count × comps`). `Reader.animValue` returns the POINT (so LINEAR/STEP reads are
  unchanged); new `animInTangent` / `animOutTangent` expose the tangents; `pack` size+write
  and `Reader.init` bounds-checking scale by `valueStride(interp)`. A v8 file with only
  LINEAR/STEP tracks is byte-identical to v7.
- **gltf.zig** maps `"CUBICSPLINE"` → interp 2 and accepts the 3× output accessor
  (`values.len == times.len · comps · 3`); the tangent-laden values pass through verbatim
  (glTF's per-key ordering already matches vmesh).
- **Sampler** (`GlSkin.sampleVec3` / `sampleQuat`, interp==2): cubic Hermite
  `p = (2s³−3s²+1)·v0 + dt·(s³−2s²+s)·outTan0 + (−2s³+3s²)·v1 + dt·(s³−s²)·inTan1`; quaternion
  = componentwise Hermite then `Quat.normalize` (glTF reference approach).
- **Demo.** A 3rd clip **Smooth** (`glskin_clip2`, button "Smooth") — jmid Z-rotation with the
  same points as Bend but non-zero tangents, so the cubic overshoots the LINEAR Bend
  mid-segment.

Tested: vmesh v8 CUBICSPLINE round-trip (point/in/out per key/comp) + LINEAR regression;
gltf CUBICSPLINE parse; `Quat.normalize`. Verified live (headed Chrome, forced-WebGL2,
Freeze on, silhouette metric): at a mid-segment time the **Smooth (cubic) pose is distinct
from Bend (linear)** while at the shared end keyframe they coincide (the difference is purely
interpolation); zero console errors. **All skinning interpolation modes (LINEAR/STEP/
CUBICSPLINE) now supported — no deferred skinning items remain.**

## Post-processing — bloom + FXAA

An offscreen post-processing path: the scene renders to an HDR render target, a
bloom + FXAA fullscreen-blit chain runs, and the result is presented to the canvas.
Both backends (WebGL2 + WebGPU), frozen to byte/FNV goldens. Demo: `/gl-post`
(`src/client/islands/GlPost.zig`) — a bright emissive cube with toggleable bloom,
FXAA, and orbit Freeze.

### Frame graph

`beginPostProcess` opens an HDR scene pass; the app emits its scene draws; then
`endPostProcess` runs the effect chain and presents:

```
scene → scene_hdr (rgba16f)         beginPostProcess: bind HDR target, draw scene
bright-pass(scene_hdr) → bloom_a    luminance > threshold, ½-res
blur H(bloom_a)        → bloom_b    9-tap separable Gaussian
blur V(bloom_b)        → bloom_a
composite(scene_hdr, bloom_a) → ldr scene + intensity·bloom, ACES tonemap
fxaa(ldr)              → canvas      edge-detect + directional blend
```

With `fxaa = false` the composite presents straight to the canvas (no `ldr` hop).
With `bloom = null` the bright/blur passes are skipped and the composite intensity is 0.

### Linear HDR scene + `variant_linear_output`

The scene shader is compiled with `variant_pbr | variant_linear_output` so it emits
**linear HDR** and skips the in-shader ACES tonemap — the composite pass tonemaps
once instead (avoiding a double tonemap). The gate is mirrored across both shader
generators: `pbrFragmentSrc` (GLSL) and `wgslPbr` (WGSL) both omit the tonemap +
gamma tail when the bit is set. For bloom to have anything to extract, the scene must
contain pixels brighter than the bright-pass threshold (e.g. an emissive material —
`GlPost` binds a 1×1 white emissive map so `emissive_factor` reaches the HDR target).

### Wire protocol

Four append-only generic tags (older interpreters size-skip them via `payload_size`),
plus `ResKind.render_target = 4`:

| Tag | Name | Payload |
| --- | --- | --- |
| 22 | `create_render_target` | `{handle, width, height, format, flags}` (flag bit0 = with depth) |
| 23 | `begin_offscreen_pass` | `{target, clear_rgba(4×f32), clear_flags}` (bit0 color, bit1 depth) |
| 24 | `end_offscreen_pass` | `{}` |
| 25 | `draw_fullscreen_quad` | `{shader, tex0, tex1, params_ptr, param_count}` |

Fullscreen draws use **no vertex buffer** — a `gl_VertexID` / `@builtin(vertex_index)`
covering triangle. Post shaders compile under `variant_post` (no VBO, no depth test,
sampler + two texture slots). The four effects share one bind layout; params are a
small f32 array per draw: bright `[threshold]`, blur `[texel.xy, dir.xy]`, composite
`[intensity]`, fxaa `[texel.xy]`.

### Encoder API

```zig
var post_ctx: gl.command.PostCtx = .{};      // persistent: target/shader handles + stable param buffers

enc.beginPostProcess(&post_ctx, .{
    .bloom = .{ .threshold = 1.0, .intensity = 0.8 },  // or null to disable
    .fxaa = true,
    .webgpu = use_webgpu,
}, width, height);
// … scene draws (setPipeline + drawPbr with variant_linear_output) …
enc.endPostProcess(&post_ctx);
```

`PostCtx` reserves fixed high resource handles (240–247) for the targets + post
shaders, emits the shaders once, and recreates the targets on resize.

### Backend notes

- **WebGL2**: color targets are FBOs with `RGBA16F`/`RGBA8` color textures (+ optional
  `DEPTH_COMPONENT24`); needs `EXT_color_buffer_float` for the HDR target.
- **WebGPU**: each fullscreen draw writes its params to its **own 256-aligned slot** in a
  shared uniform buffer (the same isolation the PBR path uses) — a single shared buffer
  would let the last draw's `writeBuffer` clobber every earlier draw before the one
  end-of-frame submit. Post pipelines are cached per `(targetFormat, hasDepth)`.

Verified via headed-Chrome CDP on both backends (real `getContext` probe, orbit frozen):
the bloom halo brightens the background outside the cube silhouette (bloom ON ≫ OFF), and
FXAA introduces anti-aliased fringe pixels along the silhouette (ON > OFF); zero console errors.

## Transparency (alpha-blend)

Verve gl supports **per-submesh alpha-blend transparency** on both backends
(WebGL2 and WebGPU). The pipeline is built into the standard PBR draw path
with no shader changes — blending is a state flag on the existing pipeline.

### Asset layer (`src/core/gl/vmesh.zig`, vmesh v9)

Each `Submesh` record carries an `alpha_mode: u32` field (4 bytes appended at
offset 72 in the 84-byte submesh struct — vmesh format version 11):

- `0` = **OPAQUE** (default; back-compat — older vmesh versions read as 0).
- `1` = **BLEND** (src-alpha / one-minus-src-alpha blending; depth writes
  disabled for the transparent pass).

### glTF parse (`src/core/gl/gltf.zig`)

The glTF parser reads `material.alphaMode`:

- `"BLEND"` → `alpha_mode = 1`.
- `"MASK"` → `alpha_mode = 2` (+ `alphaCutoff`; default 0.5) — see
  [Alpha-test cutout (MASK)](#alpha-test-cutout-mask) below.
- `"OPAQUE"` or absent → `alpha_mode = 0`.
- `doubleSided` — see [Double-sided materials](#double-sided-materials) below.

### Pipeline state (`src/core/gl/command.zig` — `state_blend = 1 << 2 = 4`)

The `state_blend` bit is set in the draw-command `state` word when a submesh
has `alpha_mode == 1`. Backends react:

- **WebGL2**: `gl.enable(BLEND)` + `gl.blendFunc(SRC_ALPHA, ONE_MINUS_SRC_ALPHA)`
  + `gl.depthMask(false)` before the draw; `gl.disable(BLEND)` +
  `gl.depthMask(true)` after.
- **WebGPU**: selects the pre-compiled `blend_pipeline` variant (created with
  `alphaBlend` descriptor) instead of the default opaque pipeline.

### Two-pass draw + back-to-front sort (`src/client/islands/GlScene.zig`)

Each frame the draw loop makes two passes over the submesh list:

1. **Opaque pass** (`alpha_mode == 0`): depth writes on, no blend.
2. **Transparent pass** (`alpha_mode == 1`): submeshes are sorted
   back-to-front by camera-space Z (centroid dot view direction) before
   drawing. Depth writes are off during this pass; the depth buffer from
   the opaque pass is read for correct occlusion. Intra-submesh
   (triangle-level) sorting is **not performed** — this is a submesh-level
   sort only, sufficient for non-intersecting geometry.

### `material:Name.baseColorA` anim target (id `0x01000008`)

The `baseColorA` field (kind=1/material, field=8) lets tweens animate the
alpha factor of any named submesh. The runtime writes `mats[s][3]` which is
uploaded to the shader as the blend alpha multiplier. Only affects submeshes
with `alpha_mode=BLEND`; opaque submeshes ignore it. The frozen id is
`0x01000008` = `16777224`; SSR emits it as `"@gl:16777224"` with
`"gh":<name_hash>` for deferred submesh resolution.

### Demo (`/gl-scene`)

The `demo.vmesh` fixture (`pbrCubeGlb`) sets `"alphaMode":"BLEND"` on its
single `Cube` material. The `/gl-scene` SSR scrub tween includes a deferred
`material:Cube.baseColorA` target (1.0 → 0.25): as the user scrolls, the
cube fades from fully opaque to 25% opacity, exercising the blend path and
the `baseColorA` anim target on both backends.

### Limits / non-goals

- **`doubleSided`** — see [Double-sided materials](#double-sided-materials) below.
- **Intra-submesh triangle sort** not implemented — per-submesh centroid
  sort is sufficient when transparent submeshes do not intersect each other.
- Alpha-to-coverage and dithered transparency are out of scope.

## Alpha-test cutout (MASK)

Verve gl supports **per-submesh alpha-test cutout** (glTF `alphaMode:"MASK"`)
on both backends. Unlike alpha-blend, MASK is **binary and order-independent**:
each fragment is either kept or `discard`ed, so cutout submeshes draw in the
**opaque pass** with depth writes on — **no blending, no back-to-front sort**.
The background shows through cutout holes with a **hard edge**, not a
translucent blend.

### Asset layer (`src/core/gl/vmesh.zig`, vmesh v10)

Each `Submesh` adds an `alpha_cutoff: f32` field (4 bytes at offset 76, growing
the submesh struct to 84 bytes — vmesh format version 11). `alpha_mode == 2`
selects MASK; `alpha_cutoff` is the discard threshold (default 0.5). Older
vmesh versions read `alpha_cutoff` as the 0.5 default.

### glTF parse (`src/core/gl/gltf.zig`)

`material.alphaMode == "MASK"` → `alpha_mode = 2`; `material.alphaCutoff` →
`alpha_cutoff` (glTF default 0.5 when absent).

### `variant_alpha_test` shader (`src/core/gl/command.zig`)

When a submesh has `alpha_mode == 2`, the renderer ORs the
`variant_alpha_test` bit (`1 << 10 = 1024`) into the submesh's shader variant.
The fragment shader (GLSL + WGSL) samples the **base-color texture alpha**,
multiplies it by the per-submesh base-color alpha factor (`u_material[0].w`),
and `discard`s (GLSL) / `discard;` (WGSL) when it is below the cutoff
(`u_material[2].w`). The cutoff is transported in `mats[s][11]`
(`alpha_cutoff`), a previously-unused material slot — non-MASK goldens are
unchanged because the discard branch is only appended in the variant.

### Draw pass (`src/client/islands/GlScene.zig`)

The opaque-pass predicate is `alpha_mode != 1`, so MASK (`== 2`) draws with the
opaque submeshes — depth-tested, depth-written, in submesh order. No sort, no
blend state.

### Dissolve via `material:Name.baseColorA`

Because the shader multiplies texture alpha by the base-color alpha factor,
animating `material:<Name>.baseColorA` 1.0 → 0.0 makes progressively more
fragments fall below the cutoff — the cutout silhouette **erodes / dissolves**.
This reuses the existing `baseColorA` anim target (id `0x01000008`); no new
target kind is needed.

### Cutout shadows — alpha-tested depth pass

A MASK submesh now casts a **hole-accurate** shadow: the depth (shadow) pass
runs the alpha test, so the cast shadow shows the same perforations as the
visible cutout, and it stays **dissolve-correct** — as `baseColorA` falls and
the silhouette erodes, the shadow erodes with it.

- **Depth-at shader (`depthAtVertexSrc` / `depthAtFragmentSrc` GLSL,
  `wgslDepthAt` WGSL).** A sibling of the plain depth shader that additionally
  forwards UV and samples the base-color texture alpha, multiplies by the
  per-submesh base-color alpha factor (`u_material[0].w`), and `discard`s below
  the cutoff (`u_material[2].w`) — the same discard logic as the color-pass
  `variant_alpha_test`, reusing the same `mats[s]` material slots so a MASK
  mesh's shadow matches its visible cutout exactly. The depth-at program is
  shader-handle 10 (`depth_at_shader`).
- **`draw_depth_at` wire tag (26).** A position-**and-UV** depth draw carrying
  the submesh's MVP (`light_vp · world`) plus the material pointer (for the
  base-texture binding + cutoff). `Encoder.drawDepthAt` emits it; the WebGL2 and
  WebGPU bridges each build a dedicated depth-at pipeline / bind group.
- **Two-phase shadow loop (`GlScene.zig`).** The shadow pass draws all plain
  (non-MASK) submeshes with `draw_depth`, then all MASK submeshes with
  `draw_depth_at`. Scenes with **no** MASK submesh are byte-identical to before.

### Demo (`/gl-cutout`)

The `cutout.vmesh` fixture (`pbrCubeCutoutGlb`) is a `Cutout` cube whose
base-color texture has a real alpha channel with **holes** (a diagonal-stripe
lattice plus a punched circular center) and an `"alphaMode":"MASK"`,
`"alphaCutoff":0.5` material, plus a large **opaque receiver plane**
(`ReceiverPlane`, mesh 1 / material 1, default OPAQUE alpha mode) at `y = -1.5`
spanning `[-6, 6]` on X/Z just below the cube. The directional light (`dir ≈
{-0.4, -0.7, -0.6}`, pointing down and away) projects the cube's alpha-tested
shadow onto the plane, so the **perforated** shadow is actually visible. The
plane's 8×8 floor texture stays in-blob (only the cube's 256² base externalizes
to `cutout.tex0.png`). The `/gl-cutout` SSR scrub tween includes a deferred
`material:Cutout.baseColorA` target (1.0 → 0.05): scrolling rotates the cube and
dissolves the cutout — and, because the depth pass alpha-tests, the cast shadow
dissolves with it. The deferred target serializes as `"@gl:16777224"` with
`"gh":<Cutout name_hash>`. (The `Cutout` submesh is still mesh 0 so the deferred
`material:Cutout.baseColorA` name resolves unchanged.)

### Limits / non-goals

- **`doubleSided`** on MASK meshes — see [Double-sided materials](#double-sided-materials).
- **Translucent (BLEND) shadows** are not implemented — a BLEND submesh casts no
  alpha-weighted shadow; the alpha-tested depth pass covers only `alpha_mode == 2`
  (MASK), where the discard is binary.
- **Animating `alphaCutoff`** is not a target — dissolve is driven via
  `baseColorA`, not the cutoff itself.

## Asset loading

gl assets (`.vmesh` geometry, `.venv` IBL, `.tex{N}.<ext>` textures) are fetched +
decoded in a dedicated same-origin module worker (`/verve-worker.js`), spawned lazily
by the bridge on the first `gl_load`. The worker `fetch`es the URL, runs a decode step
(`.png`/`.jpg`/`.webp` → RGBA via `createImageBitmap`, prefixed with an 8-byte
`[w][h]` header; `.vmesh`/`.venv` pass through), and transfers the bytes back as an
`ArrayBuffer`. The main thread then allocates in the page-scoped asset region
(`verve_asset_alloc`), copies the bytes into the shared wasm linear memory, and fires
the chunk callback (the copy must stay main-thread; the worker has its own memory). If
the worker is unavailable, CSP-blocked, or errors, `gl_load` falls back to a
main-thread `fetch` + `createImageBitmap` decode — same result. The CSP carries
`worker-src 'self'`.

**Compressed textures.** vmesh material textures over 64×64 are NOT baked raw into the
`.vmesh`: the asset-gen externalizes them to compressed sibling files
(`<stem>.tex{N}.<ext>`, PNG via `png.zig`'s adaptive MSAD-filtered DEFLATE encoder) and the vmesh
texture record carries a `format` tag (`raw` ≤64² stays in-blob, back-compat). At
runtime the chunk `gl_load`s each external texture; the worker decodes it off-main;
the chunk uploads via the usual `createTexture`. The demo's 256² base went from
~262 KB raw-in-vmesh to a ~6 KB `demo.tex0.png` (was ~11 KB with filter-None; `demo.vmesh` is now ~3 KB). GPU
still receives RGBA — this is a download + off-main-decode win, not a GPU-memory one
(GPU-compressed formats need a third-party transcoder, which the zero-dep rule
excludes).

## Double-sided materials

Verve gl supports **per-submesh double-sided rendering** (glTF `"doubleSided":true`)
on both backends (WebGL2 and WebGPU). A double-sided submesh is correctly
lit from both the front and back — the back face is neither culled (missing)
nor black (un-flipped normal).

### Asset layer (`src/core/gl/vmesh.zig`, vmesh v11)

vmesh v11 adds a `double_sided: u32` field (0=single-sided, 1=double-sided)
per submesh at byte offset 80 (struct size 84 B). The glTF parser maps
`"doubleSided":true` → `double_sided=1`; the flag is ORed into the submesh
variant as `variant_double_sided` (`1<<11 = 2048`).

### Shader (`src/core/gl/command.zig`)

The `variant_double_sided` bit selects a shader variant whose fragment stage
reads the built-in front-facing flag:
- **GLSL (WebGL2)**: `if (!gl_FrontFacing) N = -N;` before the PBR lighting call.
- **WGSL (WebGPU)**: `if (!in.front_facing) { N = -N; }` (requires `@builtin(front_facing)`
  on the fragment input struct).

All 16 PBR variant combinations (base/normal/emissive/occlusion ×
alpha-blend/alpha-test/opaque × double-sided) are covered by the handle table.

### Rasterizer state

- **Opaque and MASK (`alpha_mode != 1`) double-sided**: culling is disabled
  (`CULL_FACE` off in WebGL2; `cullMode: "none"` in WebGPU). The single draw
  call renders both faces.
- **BLEND (`alpha_mode == 1`) double-sided**: two draw calls per submesh —
  first with `CULL_FACE = FRONT` (back faces only), then `CULL_FACE = BACK`
  (front faces only) — giving the correct back-then-front composite order for
  alpha transparency. A `state_cull_front` bit (`1<<3 = 8`) in the draw
  command flags the first pass; the bridge toggles cull mode accordingly.
  WebGPU uses pre-compiled `frontCull` / `backCull` pipeline variants.

### Demo (`/gl-double`)

`/gl-double` renders a thin upright MASK quad (`"DoubleSided"` submesh,
`"doubleSided":true`, `"alphaMode":"MASK"`) positioned at the origin, with a
transparent column stripe pattern so the cutout alpha is also exercised, plus a
translucent double-sided BLEND card (`"DoubleBlend"` submesh,
`"doubleSided":true`, `"alphaMode":"BLEND"`, `baseColorFactor` alpha 0.5) offset
in +X — this exercises the two-pass back-then-front cull path. An
opaque floor plane (`"Floor"`) is single-sided. The scene auto-orbits so the
camera passes through both the front (+Z) and back (−Z) faces — the back faces
stay correctly lit via the normal-flip shader, and the BLEND card composites
correctly from either side. Verified via CDP on both backends (WebGL2 and
WebGPU): the translucent card renders, is visible from both sides, and never
culls or blackens.

**Asset:** `double.vmesh` (generated by `tools/gen_double_glb.zig` →
`gl_asset_gen` build pipeline).

### Limits / deferred items

- **Two-sided tangent handedness**: tangent W flips sign on back faces in some
  authoring tools; the current normal-flip is applied to the interpolated
  normal only — tangent/bitangent handedness is not adjusted. Practically
  invisible on the current 8×8 procedural textures but may affect high-frequency
  normal maps.
- **Double-sided shadows**: the shadow (depth) pass uses back-face culling
  for double-sided submeshes, matching conventional shadow-map practice. Thin
  double-sided surfaces (e.g. leaf cards) may under-shadow from the back side.
  Fix: disable culling in the depth pass for `double_sided == 1` submeshes.
- **Two-pass BLEND ordering**: the back-then-front two-pass approach is correct
  for convex surfaces; non-convex double-sided BLEND geometry may still exhibit
  ordering artifacts between back and front faces.

## GPU instancing

Draws N copies of a single mesh in one GPU call by encoding per-instance
transforms and attributes in the vmesh instances section. The glTF source uses
`EXT_mesh_gpu_instancing`; the asset pipeline bakes it into vmesh v12.

### Asset layer (`src/core/gl/vmesh.zig`, vmesh v12)

vmesh v12 adds an **instances section** (16-byte aligned, after the anim
section):

```
[instance_count u32] [pad to 16] [instance_count × 80 B]
```

Each 80-byte instance record is:

```
[mat4 col-major f32×16][rgba f32×4]
```

The mat4 is the composed TRS from the `TRANSLATION` / `ROTATION` / `SCALE`
instance accessors. The rgba tint comes from the `_COLOR_0` instance accessor.
When `instance_count == 0` the section is absent and `instance_off == 0` (back-compat
with vmesh v11 and earlier readers is preserved — older readers reject v12 via
`BadVersion`).

### glTF parsing (`src/core/gl/gltf.zig`)

`parseGlb` inspects the first node's `extensions.EXT_mesh_gpu_instancing`
object. It reads the `TRANSLATION` (VEC3), `ROTATION` (VEC4 xyzw), `SCALE`
(VEC3), and `_COLOR_0` (VEC4 rgba) accessors, composes each instance's TRS
into a column-major mat4, and appends `[mat4 | rgba]` to the flat `instances`
slice (`instance_count × 20 f32`). Missing `_COLOR_0` defaults to white. Only
the first node's extension is consumed; multi-mesh instancing is deferred.

### Shader (`src/core/gl/command.zig`)

`variant_instanced = 1 << 12`. When set, both the GLSL and WGSL PBR shaders
activate per-instance attributes:

- **Attribute locations 4–7**: four `vec4` columns of the per-instance model
  matrix `a_inst_m0`–`a_inst_m3`.
- **Attribute location 8**: `vec4 a_inst_color` — per-instance RGBA tint
  multiplied into `baseColorFactor` before PBR evaluation.

The vertex shader reconstructs the full mat4 from the four column attributes,
applies it to position and (via the upper 3×3 inverse-transpose) to the normal.
The `u_vp` (view-projection) uniform is reused unchanged. The fragment shader
multiplies the interpolated `v_inst_color` into `baseColorFactor`.

Wire record: `draw_pbr_instanced` (tag 27) — 9 × u32 = 36 bytes:
`[tag][geom_handle][mat_handle][bones_handle=0][shadow_handle=0][inst_buf_handle][instance_count][index_count][submesh_idx]`.

### WebGL2 backend

On `draw_pbr_instanced` (tag 27), the bridge:

1. Binds the instance VBO (created from the vmesh instances blob on `gl_load`).
2. Sets `divisor(loc, 1)` for attribute locations 4–8.
3. Calls `gl.drawElementsInstanced(TRIANGLES, index_count, UNSIGNED_SHORT, 0, instance_count)`.
4. Stores the divisor state in a dedicated per-`(vbuf, ibuf, variant)` VAO, so subsequent non-instanced draws — which bind their own VAO — are unaffected (no global divisor reset needed).

### WebGPU backend

On `draw_pbr_instanced`, the bridge:

1. Binds the instance buffer at slot 1 with `stepMode: "instance"` and `arrayStride: 80`.
2. Re-creates the `variant_instanced` render pipeline (cached by variant key) with the
   instance buffer layout declared at slot 1.
3. Calls `renderPass.drawIndexed(index_count, instance_count)`.

### GlScene draw path (`src/client/islands/GlScene.zig`)

When the loaded vmesh has `instance_count > 0` (handle 19 in the GlScene
dispatch table), GlScene:

1. Copies the instances blob into a fixed `instance_scratch[max_instances][20]f32`
   pool (max_instances = 1024).
2. Emits one `Encoder.drawPbrInstanced(geom, mat, inst_buf, instance_count, ...)` — a
   single wire record.

Non-instanced submeshes are unaffected; the instanced path is only taken when
`instance_count > 0` in the vmesh header.

### Demo (`/gl-instanced`)

`/gl-instanced` renders a 16×16 = 256-cube field from `cubefield.vmesh`
(generated by `tools/gen_cubefield_glb.zig` → `gl_asset_gen` build pipeline).
Each cube has a distinct hue (red→green→blue palette), a small per-instance yaw
rotation, and uniform scale 0.4. The 256 cubes are arranged on a 16×16 grid at
2.5-unit spacing. The scene emits a single `draw_pbr_instanced` command — one
instanced draw call on the GPU.

### Limits / deferred items

- **Per-instance culling**: the frustum-cull pass operates on the whole instanced
  submesh AABB, not per-instance. A field that partially leaves the frustum still
  issues the full draw.
- **Instanced shadows**: the shadow depth pass is not yet instanced — instanced
  geometry does not cast shadows. Fix: emit `draw_depth_at_instanced` with the
  same inst_buf in the depth pass.
- **Skinned + instanced**: combining skeletal animation with instancing is deferred.
  The two variant bits are mutually exclusive in the current shader.
- **Non-uniform-scale normals**: the per-instance normal matrix is derived from the
  upper 3×3 of the instance mat4 without inversion. Non-uniform-scale instances
  will have incorrect normals (shading artifact). Fix: pack a per-instance normal
  matrix or restrict instances to uniform scale.

## Fog

Distance fog blends each fragment toward a fog colour based on its radial distance
from the camera. Four modes are supported: `none` (disabled), `linear` (ramp from
`near` to `far`), `exp` (exponential falloff), and `exp2` (exponential-squared
falloff). Fog is applied after PBR lighting and before tonemapping, so the
fog colour is in linear space and matches the post-tonemapped clear colour only
when colours are chosen to align.

### Builder API (`src/core/gl_scene.zig`)

```zig
ctx.glScene(.{ ... })
    .fog(.{
        .mode    = .linear,         // .none | .linear | .exp | .exp2
        .color   = .{ 0.05, 0.06, 0.09 }, // linear-space RGB
        .near    = 6.0,             // linear: distance at which fog starts
        .far     = 42.0,            // linear: distance at which fog reaches full opacity
        .density = 0.05,            // exp/exp2: falloff density coefficient (default 0.05; ignored in linear mode)
    })
    .build();
```

The builder lives in `src/core/gl_scene.zig`. `.fog()` stores a `FogOpts` value;
`.build()` serialises it into the `data-glfog` canvas attribute (see Transport below).

### Wire format

`variant_fog = 1 << 13`. When set, the shaders receive fog parameters. The
8-scalar `FogParams` layout is `[mode, r, g, b, near, far, density, _pad]` where
`mode` is 0=none, 1=linear, 2=exp, 3=exp2. Distance is radial (length of the
view-space position vector), so fog is spherical rather than planar.

### Shader (`src/core/gl/command.zig`)

GLSL reads **two separate uniforms**:

- `u_fog0` — `vec4(mode, color.r, color.g, color.b)`
- `u_fog1` — `vec4(near, far, density, _pad)`

WGSL reads a `Fog` struct of two `vec4`s at `@group(0) @binding(2)`:

```wgsl
struct Fog {
  a: vec4<f32>, // [mode, color.r, color.g, color.b]
  b: vec4<f32>, // [near, far, density, _pad]
};
@group(0) @binding(2) var<uniform> fog: Fog;
```

The fog blend is applied after the PBR lighting result is computed and before
the tonemap step. The fog factor for `linear` mode is
`clamp((far - dist) / (far - near), 0, 1)`; for `exp` it is `exp(-density * dist)`;
for `exp2` it is `exp(-(density * dist)²)`.

### Transport (`data-glfog` canvas attribute)

Fog parameters are **not** carried in the GlScene `Props` struct. They travel as
a `data-glfog` canvas attribute stamped during SSR `build()` and parsed in the
chunk via `refGetAttr`. The attribute format is the comma-separated 7-scalar
string `"mode,r,g,b,near,far,density"` — for example,
`data-glfog="1,0.42,0.5,0.62,8,34,0.05"` for the `/gl-fog` demo (the trailing
`0.05` is the `FogOpts.density` default; linear mode ignores it at runtime).

The `data-glfog` transport was originally adopted on the belief that growing
`Props` tripped a wasm `decodeProps` miscompile. That turned out to be a
misdiagnosis: the blank GlScene pages were the chunk-data memory window (see the
callout under **Demo** below), not the props codec. The transport is kept anyway —
it works, ships, and keeps `Props` at the 14 fields the SSR↔chunk codec mirrors
expect (enforced by a comptime assert in `gl_scene.zig` and `GlScene.zig`). Using
the same `data-*` attribute side-channel for future per-scene parameters remains a
reasonable pattern, but it is no longer believed to be *required* by a compiler
bug.

### Demo (`/gl-fog`)

`/gl-fog` renders the same 7×7 = 49-cube grid as `/gl-cull` (`cubegrid.vmesh`),
with linear fog `near=8 far=34` and fog colour `(0.42, 0.5, 0.62)` — a soft
blue-grey haze so near cubes stay crisp while the farther cubes fade into the
fog. Camera distance is 22; the scene auto-rotates at 0.15 rad/s. Both WebGL2 and
WebGPU backends produce the same fog result.

> **Chunk-data memory window.** Island chunks share the main client's linear
> memory (`import_memory`) and the linker writes each chunk's data segments —
> including the gl chunk's comptime PBR/fog shader strings — into the region
> below the main client's own static data. The main client's stack size
> (`build.zig`) sizes that window; it is set to 4 MiB so the GlScene chunk's
> full fog shader-variant set (~1.07 MiB of data) fits. A too-small window
> silently corrupts the main client on chunk instantiation (every GlScene page
> blank, no console error) — bump the main client `stack_size` if the heaviest
> chunk's data outgrows it.

## Morph targets (blend shapes)

Morph targets (glTF "blend shapes") deform geometry by linearly blending POSITION
and NORMAL delta arrays with per-target weights. Up to K=8 active influences are
supported per draw call. Weights animate via the `morph:<i>` anim target path or
are set statically via `.morphWeights(&.{w0, w1, …})` on the `GlSceneBuilder`.

### Asset layer (`src/core/gl/vmesh.zig`, vmesh v13)

The vmesh v13 morph section (written by `gl_asset_gen` from a glTF with morph
targets) encodes a packed RGBA16F morph texture:

- **Width**: `vertex_count` texels
- **Height**: `target_count * 2` rows — row `2t` = POSITION deltas for target `t`
  (xyz packed into RGB), row `2t+1` = NORMAL deltas for target `t` (xyz into RGB)
- **Format**: RGBA16F (A channel unused, set to 1.0)
- The morph section header records `vertex_count`, `target_count`, and
  `texture_byte_length`

### glTF parse (`src/core/gl/gltf.zig`)

`parseGlb` reads `mesh.primitives[n].targets` (arrays of `{"POSITION":acc,
"NORMAL":acc}`) and `animations[n].channels` where `target.path = "weights"`.
The weight animation sampler output is a flat array of
`keyframe_count × target_count` scalars, matching the glTF spec.
`model.morph.?.target_count` reflects the target count on the first primitive with
targets.

### Shader (`src/core/gl/command.zig`)

`variant_morph = 1 << 14`. When set, the vertex shader samples the morph texture
(group(0) binding 3 = morph UBO / binding 4 = morph texture, VERTEX-visible) to
accumulate delta contributions:

```
for each active target i (i < K=8):
    weight_i = u_morph_weights[i]
    dPos += weight_i * textureFetch(morph_tex, vec2(vertex_id, 2*i)).xyz
    dNorm += weight_i * textureFetch(morph_tex, vec2(vertex_id, 2*i+1)).xyz
```

### Wire protocol

- **Wire tag 29** — `set_morph_weights`: 32-byte payload, 8 f32 weights (padded
  with zeros for unused targets). Sent once per frame when weights change.
- **Wire tag 30** — `create_morph_tex`: uploads the RGBA16F morph texture to
  the GPU. Sent once on first frame (lazy upload).

### Transport (`data-glmorph` canvas attribute)

Initial morph weights travel from SSR → hydration as a `data-glmorph` attribute
on the canvas element — a comma-separated list of f32 values (`"0.0,0.5,1.0"`).
The GlScene chunk reads this at hydration time and issues `set_morph_weights`
before the first frame. This keeps Props at 14 fields (the same conservative
guard used for fog via `data-glfog`).

### Anim path (`morph:<i>`)

The `morph:<i>` anim target path (e.g. `morph:0`, `morph:1`) animates individual
morph target weights at runtime. Used by the baked weight animation decoded from
the vmesh clip table. The path id is `0x02000000 | i`.

### Builder API (`src/core/gl_scene.zig`)

```zig
ctx.glScene(.{ .src = "/gl/morph.vmesh", .env = "/gl/studio.venv" })
    .morphWeights(&.{ 0.0, 0.0, 0.0 })   // initial weights (Props stays 14)
    .autoRotate(0.2)
    .build()
```

`.morphWeights(weights)` sets the initial `data-glmorph` attribute. The baked
clip in the vmesh plays automatically; weights animate via `morph:<i>` targets.

### Demo (`/gl-morph`)

A 5×5 subdivided plane (`morph.vmesh`, built by `gen_morph_glb.zig` at build
time) with three blend shapes:

- **Bulge**: centre vertex pushed +1.5 Y, edge midpoints +0.8 Y, corners +0.3 Y
- **Wave**: sine deformation along X (amplitude 0.8)
- **Twist**: vertices rotated around Y proportional to their Z coordinate

The baked `MorphDemoAnim` clip (LINEAR, 3 s total) cycles through each target
weight in sequence: k0=[0,0,0] → k1=[1,0,0] → k2=[0,1,0] → k3=[0,0,1].

### Limits / deferred items

- **Skinned + morph**: combining `variant_skinned` and `variant_morph` is
  deferred. The two variant bits are mutually exclusive in the current shader.
- **TANGENT deltas**: morph targets with TANGENT deltas are not yet parsed or
  applied. Only POSITION and NORMAL deltas are decoded.
- **>8 active targets**: the shader supports K=8 influences. Assets with more
  than 8 morph targets silently use only the first 8.
- **CUBICSPLINE Hermite easing**: the weight sampler treats CUBICSPLINE keyframes
  as LINEAR (tangents ignored). Full Hermite easing is deferred.

## Depth + view-space normal prepass (G-buffer)

The **prepass** renders scene geometry once into a normal+depth **G-buffer**
*before* the main PBR pass. It is the foundation for screen-space image-quality
effects (SSAO, SSR, DOF) that arrive in later slices. There is no user-visible
output of its own; a debug visualization on `/gl-post` confirms it works.

### Output

A single `rgba16f` render target (`PrepassCtx.h_gbuffer` = handle **248**, created
with depth):

- `rgb` = view-space normal encoded as `normal * 0.5 + 0.5`
- `a`   = `-viewPos.z` — linear view-space depth, positive in front of the camera

### Approach — separate prepass, not MRT

A dedicated stripped shader pair renders geometry into the G-buffer in its own
offscreen pass. MRT was rejected: it would fork every scene pipeline and every
fragment return struct across both backends, a lockstep-bug class with no native
test coverage. The prepass shader is standalone (`variant_prepass = 1 << 16`),
not a PBR add-on, so it never touches the `PBR_U` uniform layout.

### Reconstruction data placement

To keep `PBR_U` byte-identical:

- The prepass shader has its own **128-byte** UBO `{ mvp @0, mv @64 }` — `mvp` =
  proj·view·model (clip position), `mv` = view·model (view-space position +
  normal transform).
- `inv_proj` (for future screen-space view-position reconstruction) rides the
  **post params buffer**, which grows 32 → 80 bytes. It is *not* added to
  `PBR_U`.

### Wire surface (`src/core/gl/command.zig`)

- `variant_prepass = 1 << 16`.
- `draw_prepass` tag **39**: `{ vbuf, ibuf, off, count, mvp_ptr, mv_ptr }` —
  mirrors `draw_depth` (tag 19) plus the `mv` pointer.
- `wgslPrepass()` + GLSL `prepassVertexSrc`/`prepassFragmentSrc`.
- `wgslGbufferDebug()` + GLSL `gbufferDebugFragmentSrc()` — a `variant_post`
  fullscreen debug shader (reuses tag 25, `draw_fullscreen_quad`). `params.x`
  selects the mode: `0` = view normals (rgb), `1` = linearized depth grayscale
  (alpha).
- `PrepassCtx` (handles `h_gbuffer`=248, `sh_prepass`=249, `sh_gdebug`=250; 251
  spare) with `beginPrepass` / `drawPrepass` / `endPrepass`, mirroring the post
  path: the island opens the prepass, re-emits geometry via `drawPrepass`, then
  closes it — all *before* `beginPostProcess`.

### Both backends

- **WebGPU**: `variant_prepass` builds a "prepass" pipeline (single `rgba16float`
  color target, depth-write on, 128B dynamic-offset UBO). The offscreen RT depth
  texture gains `TEXTURE_BINDING` so a future slice *can* bind hardware depth (no
  depth sampler is wired yet).
- **WebGL2**: a prepass program + a `:pp`-keyed VAO (pos@0, normal@12 over the
  stride-48 layout) draws into the G-buffer FBO; the debug viz goes through the
  existing fullscreen-quad path. WebGL2 offscreen depth is already a sampleable
  `DEPTH_COMPONENT24` texture.

### Demo (`/gl-post`)

The "Toggle G-buffer" button (`glpost_toggle_gbuffer`) switches the frame to the
prepass path: render the cube into `h_gbuffer`, then blit `sh_gdebug` straight to
the canvas (bypassing the lit scene + post chain). "G-buffer Mode" toggles
between view-normals and linearized-depth (`glpost_toggle_gbuffer_mode`). With
normals mode on, a front-facing cube-face center pixel reads ≈ `(128, 128, 255)`
(a +Z view-space normal); depth mode renders the near cube darker than the far
background.

## Image-quality slice 2: tone-mapping operators + vignette (v0.13.0)

The composite stage now carries a selectable tone-mapping operator and an
optional vignette, packed into the existing 16-byte composite params slot:
`{ intensity: f32, tonemap: f32, vig_intensity: f32, vig_radius: f32 }`.

### Tone-mapping operators

`PostProcess.tonemap: ToneMap = .aces`. Select via the enum:

| Index | `ToneMap` variant | Formula | Notes |
|-------|------------------|---------|-------|
| 0 | `linear` | `pow(clamp(hdr,0,1), 1/2.2)` | Clips highlights to white |
| 1 | `reinhard` | `x=hdr/(1+hdr)`, gamma 2.2 | Soft rolloff |
| 2 | `reinhard_ext` | `x=hdr*(1+hdr/16)/(1+hdr)`, gamma 2.2 | W=4, brighter shoulder |
| 3 | `aces` **(default)** | Hill fit `(a,b,c,d,e)=(2.51,0.03,2.43,0.59,0.14)`, **no gamma** | Byte-identical to pre-v0.13 composite |
| 4 | `agx` | `clamp(x/(x+0.155)*1.019, 0, 1)` per channel | Filament/Hyper approximation; neutral, no hue-shift |
| 5 | `uncharted2` | Hable curve, exposure-bias 2, white-scale W=11.2, gamma 2.2 | Crushed blacks, filmic |

All six operators are implemented identically in WGSL (`wgslComposite`) and
GLSL (`compositeFragmentSrc`). Operator 3 (ACES) reproduces the pre-slice-2
output byte-for-byte — `/gl-post` is unchanged.

**AgX approximation note:** The AgX implementation uses the Filament/Hyper
3-term polynomial `y = x/(x+0.155)*1.019` (per channel, clamped), not the
full AgX matrix + CDL pipeline. It is deterministic, identical on both
backends, and visually close to the neutral AgX look.

### Vignette

`PostProcess.vignette: ?Vignette = null`. Enable with:

```zig
enc.beginPostProcess(&post_ctx, .{
    .tonemap = .aces,
    .vignette = .{ .intensity = 0.85, .radius = 0.65 },
}, width, height);
```

Applied **after** tone-mapping in the same composite shader pass (no extra pass):

```glsl
float d = length(v_uv - vec2(0.5));
float v = smoothstep(vig_radius, vig_radius - 0.45, d);
rgb *= mix(1.0, v, vig_intensity);
```

`intensity=0` is a no-op (the default). `radius` controls where darkening
begins (0.65–0.80 are typical values).

### Wire contract

No new wire tags. The composite `drawFullscreenQuad` now passes `param_count=4`
(was 1), so all four floats reach the bridge. Bridge paths:
- **WebGL2**: `applyPostParams` resolves `u_tonemap`, `u_vig_intensity`,
  `u_vig_radius` at shader-create time and applies them per draw.
- **WebGPU**: existing `Float32Array(8)` loop already reads up to 4 floats;
  they land at `arr[0..3]` and are uploaded via `writeBuffer` per draw slot.

## Image-quality slice 3: SSAO (screen-space ambient occlusion) (v0.14.0)

The first **consumer** of the slice-1 G-buffer. SSAO computes how occluded each
fragment is by nearby geometry and multiplies that ambient-access term into the
scene before bloom + tonemapping — darkening creases, contacts, and concavities.

### Pipeline (driven by the island per frame)

```
prepass(scene → h_gbuffer)              # depth + view-space normals (slice 1)
runSsao(h_gbuffer → h_ao_raw → h_ao_blur)
scene → h_scene_hdr                      # lit PBR (variant_linear_output)
composite(scene_hdr × AO + bloom) → fxaa → canvas
```

`Encoder.runSsao(ctx, webgpu, w, h, radius, bias, intensity, &inv_proj, &proj)`
emits the two SSAO passes; `beginPostProcess(.{ .ao_tex = h_ao_blur, ... })` binds
the blurred AO at the composite's `tex2`.

### View-space position reconstruction (the critical part)

The G-buffer stores **linear view depth** in alpha: `a = -viewPos.z` (positive;
the camera looks down `-Z` in view space). To rebuild the full view-space
position from a UV + that depth:

```
ndc      = uv * 2 - 1
v        = inv_proj * vec4(ndc, 1.0, 1.0)
viewRay  = v.xyz / v.w           // direction from the origin; viewRay.z < 0
viewPos  = viewRay * (depth / -viewRay.z)
```

The scale `depth / -viewRay.z` makes `viewPos.z == -depth` exactly (depth > 0,
viewRay.z < 0 → positive scale). A fragment with `depth <= 0` is background
(cleared to 0) → AO = 1.

### AO computation (identical in WGSL + GLSL)

- normal `n = normalize(g.rgb * 2 - 1)` (view space).
- per-pixel rotation from a hash of the UV (`fract(sin(dot(...))*43758.5453)`),
  Gram-Schmidt → a TBN. **No noise texture.**
- a hardcoded **16-sample** hemisphere kernel (tangent space, z toward the
  normal, clustered near the origin), identical constants both backends. **No UBO.**
- each sample: `samplePos = viewPos + TBN*kernel[i]*radius`, re-projected with
  `proj` to a screen UV; the stored geometry depth at that UV (`tex0.a`) is
  compared to the sample point's depth (`-samplePos.z`) with a `bias` and a
  `smoothstep` range check. `ao = 1 - (occlusion/16) * intensity`.
- a 4×4 **box blur** removes the per-pixel rotation noise (`h_ao_raw → h_ao_blur`).

### Wire / params surface (`src/core/gl/command.zig`)

- `SsaoCtx`: `h_ao_raw=251`, `h_ao_blur=252` (full-res `rgba16f`, AO in `.r`),
  `sh_ssao=253`, `sh_ssao_blur=254` — immediately after `PrepassCtx`'s 248–250.
- `draw_fullscreen_quad` (tag 25) gains a **third texture**:
  `{ shader, tex0, tex1, tex2, params_ptr, param_count }` (24B). The shared post
  bind group adds `@group(1) @binding(3) var tex2` (WGSL) / `u_tex2` (GLSL). When
  `tex2 = 0` the bridge binds a **1×1 WHITE** texture (AO = 1.0), so any post
  effect that doesn't bind AO (`/gl-post`, `/gl-tonemap`) is a no-op.
- The post params buffer is **144B**: `{ params:vec4 @0, inv_proj:mat4 @16,
  proj:mat4 @80 }`. `inv_proj` was already plumbed (slice 1, zero); `proj` is new.
  SSAO uploads 36 f32 (`params = (radius, bias, intensity, _)` + both matrices).
  PBR_U / the WGSL `U` struct are **untouched**.

### Demo (`/gl-ssao`)

A floor plane with five cubes resting on it (contact/crease geometry). Controls
(`glssao_toggle` / `glssao_toggle_view` / `glssao_freeze`):

1. **Freeze**, then **Toggle SSAO** — the cube-cube gaps and cube-floor contacts
   DARKEN with AO on, and read uniform with it off.
2. **Toggle AO View** — blits the raw AO buffer: dark in crevices, white on open

## Image-quality slice 4: SSR (screen-space reflections) (v0.15.0)

The second **consumer** of the slice-1 G-buffer. SSR ray-marches the reflection
of the view vector in screen space against the G-buffer, samples the lit scene
at hits, and blends the reflection into the scene with a uniform strength and a
Fresnel term.

### Pipeline (driven by the island per frame)

```
prepass(scene → h_gbuffer)              # depth + view-space normals (slice 1)
scene → h_scene_hdr                     # lit PBR, linear HDR (post path)
runSsr(h_gbuffer + h_scene_hdr → h_scene_ssr)   # scene + reflections
bloom bright-pass + composite(scene_src = h_scene_ssr) → canvas
```

`beginPostProcess` opens the scene HDR pass; the island draws the scene, closes
the pass, calls `runSsr(...)` (which reads `h_gbuffer` at tex0 + `h_scene_hdr` at
tex1, writing `h_scene_ssr`), then calls `endPostProcess` with
`PostProcess.scene_src = h_scene_ssr` so the bloom/composite chain reads the
scene+reflections target instead of the raw HDR scene.

### View-pos reconstruction + reprojection

Reuses the **exact** slice-3 `reconstructView` (G-buffer alpha = `-viewPos.z`,
positive; camera looks down `-Z`). The march reflects `viewDir = normalize(viewPos)`
around the view-space normal, steps a **fixed 32 steps** up to `max_distance`, and
reprojects each marched point `p` to screen UV with `clip = proj * vec4(p,1);
uv = clip.xy/clip.w * 0.5 + 0.5` — identical to SSAO's hemisphere reprojection
(same `0.5+0.5` and y-orientation for both backends). A hit is when the marched
point's depth is just past the stored G-buffer depth within `thickness`.

### Reflection (identical in WGSL + GLSL)

On a hit, the scene HDR is sampled at the hit UV and added:
`scene + reflColor * (strength * fresnel * mask)`, where `fresnel =
pow(1 - max(dot(-viewDir, n), 0), fresnel_power)` (Schlick — grazing angles
reflect more) and `mask` is a screen-edge fade. No hit / background → the
unmodified scene color, so `h_scene_ssr` is a drop-in replacement for
`h_scene_hdr`. WGSL uses `textureSampleLevel(...,0.0)` for every read (the march
is non-uniform control flow; bare `textureSample` would be illegal).

### Wire / params surface (`src/core/gl/command.zig`)

- `SsrCtx`: `h_scene_ssr=255` (rgba16f full-res scene+reflections), `sh_ssr=256`
  (variant_post) — immediately after `SsaoCtx`'s 251–254. No collision.
- Rides the **existing 144B post Params** `{params:vec4 @0, inv_proj:mat4 @16,
  proj:mat4 @80}` where `params = (reflection_strength, max_distance, thickness,
  fresnel_power)`, and the existing shared 3-texture bind group. **No new wire
  tags, no Params-size change, no bind-group surgery.** PBR_U untouched. The only
  bridge change is adding `sh_ssr=256` to the WebGPU 144B binding-size branch.
- `PostProcess.scene_src` (default `0` → `h_scene_hdr=240`) parameterizes the
  bloom/composite chain's scene source; existing demos leave it `0` and render
  byte-for-byte as before (goldens frozen).

### Scope: GLOBAL SSR (material-aware deferred)

GLOBAL SSR with a **uniform** reflectivity × Fresnel — **not material-aware**.
The G-buffer stores only normal + depth (no roughness/metalness), so
roughness-weighted / material-aware SSR is **deferred**: it needs a G-buffer
material channel (i.e. **MRT**), which the foundation deliberately rejected.

### Demo (`/gl-ssr`)

A dark, smooth reflective floor with several bright emissive cubes floating above
it (asset-free — reuses the built-in plane/cube meshes). Controls
(`glssr_toggle` / `glssr_toggle_view` / `glssr_freeze`):

1. **Freeze**, then **Toggle SSR** — the floor shows an **inverted reflection** of
   the cubes above it (appears below the surface) with SSR on, and reads as a
   matte floor (no reflection) with it off.
2. **Toggle View** — blits the raw SSR target (scene + reflections) straight to
   the canvas.

Both WebGPU and WebGL2 backends must agree, with a clean console (no WGSL/WebGPU
validation errors). `/gl-post`, `/gl-tonemap`, and `/gl-ssao` must look unchanged
(`scene_src` defaults to `h_scene_hdr` → no-op).

## Image-quality slice 5: DOF (depth of field) (v0.16.0)

The third **consumer** of the slice-1 G-buffer — and the simplest. DOF blurs the
scene by a **circle-of-confusion** (CoC) derived from each pixel's linear view
depth relative to a focus distance, compositing sharp vs blurred. **No matrices**
(depth comes straight from the G-buffer alpha); the two blur passes **reuse**
`PostCtx.sh_blur`, so only ONE new shader is created.

### Pipeline (driven by the island per frame)

```
prepass(scene → h_gbuffer)             // depth + view-space normals (slice 1)
scene → h_scene_hdr                    // lit PBR, linear HDR (post path)
runDof(blur H + blur V + CoC combine → h_scene_dof)  // slice 5 DOF
composite(scene_src = h_scene_dof × AO + bloom) → canvas
```

`runDof` emits: (1) `sh_blur` `h_scene_hdr` → `h_dof_a` (dir `(1,0)`), (2)
`sh_blur` `h_dof_a` → `h_dof_b` (dir `(0,1)`, fully blurred scene), (3) `sh_dof`
combine `(h_scene_hdr sharp, h_dof_b blurred, h_gbuffer depth)` → `h_scene_dof`.

### CoC combine (identical in WGSL + GLSL)

```
depth = gbuffer.a              // -viewZ (positive); depth <= 0 → background → coc = 0
coc   = clamp(abs(depth - focus_distance) / focal_range, 0, 1) * max_blur  // max_blur ∈ [0,1]
out   = mix(sharp, blurred, coc)
```

Depth is **positive linear view depth** (the prepass writes `a = -viewPos.z`); a
pixel exactly at `focus_distance` is fully sharp, pixels `focal_range` or further
away reach `max_blur`. Background (`depth <= 0`) stays sharp.

### Wire / params surface (`src/core/gl/command.zig`)

- `DofCtx`: `h_dof_a=257`, `h_dof_b=258` (blur ping-pong), `h_scene_dof=259`
  (sharp+blur composite), `sh_dof=260` (variant_post combine) — immediately after
  `SsrCtx`'s 255–256. No collision. The blur passes reuse `PostCtx.sh_blur=245`.
- The combine params are a single **vec4** `(focus_distance, focal_range,
  max_blur, _)` → auto-derived **32B** WebGPU `paramsSize` (the slice-4
  WGSL-derived binding-size path needs no change). The blur passes use the same
  4-float `(texel.xy, dir.xy)` params as the bloom blur. **No new wire tags, no
  Params-size special-casing.** PBR_U untouched. The only bridge change is a
  `u_dof_params` uniform mapping for the GLSL combine (vec4 at `count=4`).
- Reuses slice-4's `PostProcess.scene_src` (default `0` → `h_scene_hdr=240`);
  existing demos leave it `0` and render byte-for-byte as before (goldens frozen).

### Demo (`/gl-dof`)

A row of 7 bright emissive cubes receding from near to far along the view axis so
each sits at a distinct linear view depth (asset-free — reuses the built-in cube
mesh; per-object transform/material arrays per the aliasing rule). Controls
(`gldof_toggle` / `gldof_focus_near` / `gldof_focus_far` / `gldof_toggle_view` /
`gldof_freeze`):

1. **Freeze**, then **Toggle DOF** — with DOF on, cubes far from the focus band
   blur while the focus band stays sharp; off → all cubes sharp.
2. **Focus Near / Focus Far** — step `focus_distance` so the sharp band sweeps
   through the depth range (the nearest then farthest cubes come into focus).
3. **Toggle View** — blits the raw DOF target (`h_scene_dof`) straight to canvas.

Both WebGPU and WebGL2 backends must agree, with a clean console (no WGSL/WebGPU
validation errors). `/gl-post`, `/gl-tonemap`, `/gl-ssao`, and `/gl-ssr` must look
unchanged (`scene_src` defaults to `h_scene_hdr` → no-op).
